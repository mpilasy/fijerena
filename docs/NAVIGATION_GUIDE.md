# Navigation Guide

Type-safe navigation with Navigation Compose and kotlinx.serialization routes. The routes live in `:core:navigation`; each app has its own nav host: `tv/.../navigation/TvNavHost.kt` and `mobile/.../navigation/MobileNavHost.kt`. Module layout: [design.md](design.md#module-architecture).

## Screen Definitions

`core/navigation/.../Screen.kt`:

```kotlin
sealed interface Screen {
    @Serializable data object ProviderSelection : Screen  // "Sources"
    @Serializable data class AddProvider(val editId: Long = -1L) : Screen  // add, or edit when editId > 0
    @Serializable data object Login : Screen  // in neither nav graph
    @Serializable data object ProfilePicker : Screen  // "Who's Watching?"
    @Serializable data class ProfileEdit(val profileId: String, val admin: Boolean = false) : Screen  // a profile's page (mobile; TV shows it inside Settings); admin = Admin → Profiles, with the Admin rows
    @Serializable data object ContentTypeSelection : Screen  // Home
    @Serializable data object Settings : Screen  // also the phone's Settings tab
    @Serializable data object LiveTvTab : Screen  // a section's root: phone tab, TV rail section
    @Serializable data object MoviesTab : Screen
    @Serializable data object TvShowsTab : Screen
    @Serializable data object HomeTab : Screen  // the phone's Home tab root (every section's rows)
    @Serializable data class CategoryList(
        val contentType: String, val initialCategoryId: String? = null,
        val initialStreamId: String? = null, val showPreviewPane: Boolean = true,
        val providerId: Long = 0L,
    ) : Screen
    @Serializable data class TmdbTitle(
        val contentType: String, val tmdbId: String, val title: String,
        val originalTitle: String? = null, val year: Int? = null, val posterPath: String? = null,
    ) : Screen  // a film or show no source may have (wanted titles plan); replaced by its source copy's page once a source has it
    @Serializable data class EpisodeSelection(
        val seriesId: String, val seriesName: String, val categoryId: String,
        val initialEpisodeId: String? = null, val providerId: Long,
    ) : Screen
    @Serializable data class MovieDetails(
        val movieId: String, val movieName: String, val categoryId: String, val providerId: Long,
    ) : Screen
    @Serializable data class Search(
        val contentType: String, val initialQuery: String? = null,
        val initialTypeFilter: String? = null,  // phone: the section chip preselected
        val initialGuideTab: Boolean = false,   // phone: opened on its Guide tab
        val initialSource: Long? = null,        // phone: the source filter brought along
    ) : Screen
    @Serializable data class EpgGuide(
        val categoryId: String, val categoryName: String, val focusChannelId: String? = null,
        val providerId: Long,
    ) : Screen  // TV Guide
    @Serializable data class EpgBrowser(
        val categoryId: String? = null, val categoryName: String? = null, val providerId: Long = 0L,
    ) : Screen  // "Search the Guide"; categoryId/providerId: the TV Guide it was opened from
    @Serializable data class EpgManagement(val providerId: Long = 0L) : Screen  // every source's guide sources, grouped; providerId opens on that source's group, 0 at the top
    @Serializable data object SyncSettings : Screen  // Live sync
    @Serializable data object ParentalControls : Screen  // mobile; TV shows it inside Settings
    @Serializable data class ParentalListEdit(val listKey: String) : Screen  // mobile: one Parental controls list
    @Serializable data class ParentalCheck(val providerId: Long) : Screen  // mobile: Check a source
    @Serializable data object Diagnostics : Screen  // Logs: Settings → About, everyone with Settings; also from SafeMode
    @Serializable data object DeviceInfo : Screen  // Settings → About, everyone
    @Serializable data object SafeMode : Screen  // start destination after a crash loop (SafeMode.isActive)
    @Serializable data object NewerData : Screen  // start destination when providers.db is from a newer build (ProvidersDbGuard.isBlocked)
    @Serializable data class Player(
        val streamId: String, val streamName: String, val categoryId: String, val contentType: String,
        val episodeId: String? = null, val episodeExtension: String? = null,
        val seriesId: String? = null, val seriesName: String? = null,
        val startFromBeginning: Boolean = false,
        // Catch-up: the archive window of live channel streamId (contentType LIVE_TV), played like a
        // film; null plays the stream itself. Watch live replaces the player with the channel's
        // preview (TV) / dock (phone), so Back returns where the catch-up was opened from.
        val catchupStartSec: Long? = null, val catchupDurationSec: Long = 0L,
        val catchupOffsetSec: Long = 0L, val programTitle: String? = null,
        val providerId: Long,
    ) : Screen
}
```

All IDs are `String` so Xtream (numeric), Jellyfin (UUID), SMB and Local (paths) fit the same routes. `showPreviewPane` is read by TV only (see [Live TV preview / dock](#live-tv-preview--dock-back-stack)).

**A route's source.** `CategoryList`, `EpisodeSelection`, `MovieDetails`, `EpgGuide` and `Player` (and `catchupRoute`, which builds a catch-up `Player`) carry the source they open on, `providerId`. Every one but `CategoryList` names a real source (no default; multi-source plan, Phase 6); a `CategoryList` with `0` is a section's list, every Xtream source of the profile merged (a row or category of it carries its own source, and a virtual list's falls back to the list's own, the profile's first Xtream source). The screen's view model reads that source's repository (`AppContainer.getMediaRepository(providerId)`), its header names that source, and every route it opens copies the id: details → Player, a related title or the category button, episodes → Player, the TV Guide → a channel's preview or catch-up, catch-up's Watch live, a list's rows, guide and Start over. A row of the merged lists — Recent, Favourites, Recent Categories and Home's Continue watching, Channels, favourite and TMDB chart rows, which mix the profile's sources (Phase 4) — opens on its own source (`MediaItem.providerId`, `ContinueWatchingItem.providerId`), not the list's: a Home channel opens a Live TV `CategoryList` on that channel's source, and a Recent Categories row of a source the list doesn't hold pushes that source's `CategoryList` on the category (Back returns to the list it came from). See `docs/plans/20261012_multi-source-search-history-plan.md` → Phases 1 and 4.

**Merged browsing (Phase 6, part 1).** A section's list (`providerId` 0) is built around the profile's first Xtream source (`MergedLists.browsingProviderId`), not the active one, and lists every Xtream source's categories of the profile: `MediaCategory.providerId` tags each, `MediaCategory.key` (`"<source>/<id>"`; a virtual category's id alone) is what list keys, pane / focus keys, the selection (`UiState.Success.selectedCategoryKey`, saved with its source) and favourite-category stars go by. `CategoryList(providerId = P)` lists the same merged categories with `initialCategoryId` on P. Picking a category is `loadStreams(id, source)`; its rows are stamped with their source and every per-row map (stars, progress, watched, Now, catch-up days) is keyed by `MediaItem.sourceKey`. A Recent / Favourite Categories row of any merged source selects its category in place; its favourite toggles the category on the row's source. The TV Guide (header button, the OSD's Guide) and Start over open on the category's or channel's own source. Jellyfin and M3U sources are not merged: a **Browse <source>** entry (TV rail item below the sections, `TvNavRail(browse, onBrowse)`; phone profile sheet row) resolves the source's sections (`ProfileSections.opening`) and pushes `CategoryList(contentType, providerId = source)` (TV: `showPreviewPane = false`, browse with the preview layer) over where you are, a dialog asking which section when it has several, `AddProvider(editId)` when this profile has no login for it. Back returns to where you were; the rail's lit item doesn't change.

### Back-Stack Rules

1. **Pushes use `navigateOnce`** (`core/navigation/.../NavExtensions.kt`): it navigates only while the current entry is RESUMED, so a D-pad auto-repeat or a double tap during a transition can't push a screen twice. The sign-in prompt and the profile / external switches below use plain `navigate`, since they fire while Home may still be entering.
2. **Start destination**: `NewerData`, then `SafeMode`, are checked before anything else. Both skip the nav host's `initializeStartup()` (provider lookups, legacy-credential migration, profile count): `NewerData` because nothing may open `providers.db`, `SafeMode` because that work may be what keeps crashing. Back on either leaves the app; `SafeMode`'s Show diagnostics pushes `Diagnostics` and Back returns to it. Continue / Reset sources restart the process. See the next level rock solid resilience plan → R-10, R-01. Otherwise, when a source exists, Home on TV (through `ProfilePicker` when there are two or more profiles) and on the phone the last tab used (Rule 7). With no source at all (the settings flow review, E1): an admin in use starts on `Settings` with `AddProvider()` pushed over it once (`startsOnAddSource`; Back goes to Settings), and the first source saved there (no source before it, `opensHomeAfterSave`) clears the back stack and opens Home (TV `ContentTypeSelection`, phone the Home tab), after `clearAllCaches()`; a later source or an edit goes back as before. Startup calls `ProfileRepository.ensureAnExpert` first, so a new install's first profile is an admin. A profile that is not an admin starts on Home, which asks a grown-up for a source.
3. **Back on the root never leaves the app** (household UX plan, 2026-10-19): on TV, Back on Home does nothing, nor on the launch profile picker or on Settings when it is the start destination; on mobile Back on a tab's root goes to Home (`selectTab`), and on Home does nothing — a `BackHandler` composed before the NavHost, so popping a screen and a screen's own Back (Live TV's dock) come first. Leaving is the device's Home button.
4. **Profile switch, live-sync switch**: TV navigates to Home and clears the whole back stack (`popUpTo(navController.graph.id) { inclusive = true }`); the phone's `startOver()` (`MobileNavHost.kt`) re-reads the profile's sources, stops the Live TV dock, clears every tab's saved stack (`clearTabStacks()`) and opens the profile's last tab with `popUpTo(graph.id) { inclusive = true }` — so no screen holding the previous profile's (closed) repositories survives underneath. A profile switch moves no source (there is none in use since multi-source Phase 6): the lists reload over the new profile's sources. When another device deletes the profile in use here, live sync moves this device to another (a child profile only to another child; with none, it stays on the child, `AppContainer.askWhoIsWatching`, so the child lock applies on the picker) and drops every screen, playback included, to ask who is watching (`AppContainer.externalSwitches`): TV opens `ProfilePicker` as the only screen, the phone starts over and opens the profile menu with only the profiles, which stays (no swipe, scrim tap or Back closes it) until one is picked. Live sync starts over (without asking) when another device deletes a source the profile in use has (`AppContainer.sourceDeletions`) — that one only once nothing plays (the player closed; on the phone, no docked live channel either), since a stream doesn't need its source's settings. A deleted source the profile doesn't have changes nothing on screen: only its cached repository goes.
5. **Remote Stop (Live sync)**: when another device of the sync group stops this device's playback, whichever playing screen is up — TV `TvPlayerScreen` or the `LiveTvSplitLayout` preview / full screen, mobile `MobilePlayerScreen` or the Live TV dock (docked or full screen) — finalises the session as Back does, stops, and pops back to Home on TV (`popBackStack(Screen.ContentTypeSelection, inclusive = false)`, the screens' `onHome`), to the Live TV tab's root on the phone (`openLiveTvRoot`; the start tab when the source has no Live TV) with a "Playback stopped from <device>" toast. See `RemoteStopEffect` and the live sync now playing plan → Remote Stop.
6. **TV navigation rail** (`tv/.../ui/components/rail/`, `navigation/TvSections.kt`, the tv nav rail plan): a thin rail of faint icons in the left margin of every TV screen — profile, Home, the sections (the union of the profile's Xtream sources', `ProfileSections.merged`; none with no Xtream source), a Browse item per Jellyfin / M3U source of the profile, Search, Settings at the bottom (not for a child profile); the TV Guide is not on it. Left from a screen's leftmost item (`Modifier.leftToRail()`) slides it out over a scrim with labels, on the item you are in (`TvNavRailState.current`); Right returns to the item Left came from (`returnTo`); Back in the rail goes to Home (on Home, back to the content). Sections (Live TV only when an Xtream source has channels, as on the phone) are the tab routes the phone uses (`Screen.LiveTvTab` / `MoviesTab` / `TvShowsTab`, each hosting `TvCategoryGridScreen`), Home's single-section auto-skip opens them too: `navigate(section) { popUpTo(Home) { saveState = true }; launchSingleTop = true; restoreState = true }`, so each keeps its place (a film's details included); the section you are in goes back to its start; from Settings or Search opened over a section, that section's item goes back to where you were in it. Settings-tree screens (Settings, Sources, Add / Edit Source, Guide sources, Live sync, Device info, Diagnostics) are dropped before a section switch. Back at a section's start focuses the rail instead of leaving; Back again goes Home. Search on the rail opens the current section's search (everything from Home and Settings); when a section's search finds nothing, its empty state has **Search everything**, which reopens Search over everything with the same words. Hidden (`HideTvNavRail()`) on the player, the Live TV preview layer, the profile picker, Add / Edit Source, safe mode, newer data, and while the profile has no source. Leaving Live TV with its preview saved open closes it (`closeSavedLivePreview`) so it doesn't play on return. A profile or live-sync switch clears the sections' saved places (`clearSectionStacks()`), and the rail re-reads the profile's sections on every destination change. First launch: the rail slides out once with "Press Left for sections". Replaces the section-root button (removed 2026-10-08).
7. **Phone tabs** (`navigation/MobileBottomBar.kt`, the phone home overhaul plan, `docs/plans/20261019_phone-home-tab-plan.md`): a bottom bar with Home first (`MobileTab.HOME`, root `Screen.HomeTab`: `MobileHomeScreen`, the rows of every section; a card is pushed inside the Home tab), then a tab per section (`ProfileSections.merged`: the profile's Xtream sources' merged sections; Live TV only when a source has channels), then the profile slot (the Search tab of 2026-10-10 gave its place to Home on 2026-10-19: Search over everything is Home header's Search) (`MobileTab.SETTINGS`, root `Screen.Settings`, no back arrow): it shows the profile in use (avatar over name, with a gear badge: `ProfileSettingsAvatar`, also on the tab header's avatar when there is no bar) and opens the profile menu (`MobileProfileMenu`: the profiles, Settings, the Browse entries), lit while in Settings — so a single section shows the bar too, with Home; under 380 dp wide (`showsTabLabels`) the tabs show icons only, the name in a long-press tooltip and as the content description; no section (no Xtream source: the tab root shows a Browse button per source, or Add Source with none — for an admin only; others read "Ask a grown-up to add one"), no bar. Each tab's root is its own route — `Screen.LiveTvTab` / `MoviesTab` / `TvShowsTab`, rendering the section's `MobileCategoryListScreen` with the tab header (`MobileSourceTopBar`: the sources' sync summary) — because Navigation keys saved back stacks by destination and the three `CategoryList(type)` entries share one. Switching tabs: `navigate(tab) { popUpTo(graph.id) { saveState = true }; launchSingleTop = true; restoreState = true }`, so each keeps its place; tapping the current tab pops to its root. Only one tab's stack is on the back stack at a time, so Back on a tab root leaves the app. The bar shows on every screen inside a tab — its root and what's pushed on it: details, episodes, category lists, Search, guides (`tabOf(backStack)`: the one tab root on the stack) — so tapping the current tab pops back to its start from anywhere in it, and a tab switched away from comes back on the screen it was on. Hidden on the player and the two forms, Add / Edit Source and a profile's page (`hidesBottomBar`); Settings and the rest of what it opens keep it. Also hidden while a Live TV dock covers the screen (full screen, PiP, the landscape split) — each dock, the tab root's or one pushed deeper (a channel opened from Search or a guide), reports itself by back-stack entry, so the screen leaving can't clear the one arriving. Leaving a tab stops every dock in it, as Back does. The start destination is `startTab(AppSettings.lastTab, sections)`: the profile's last tab if its sources have it, else Home — never Settings. A pushed `CategoryList` (Search, guides, a details screen's category) keeps its own bar with the back arrow. A Search result of another section opens in that section's tab (`openInSectionTab`): the tab searched from is popped to its root (so its saved place doesn't keep the search), the result's tab is selected as the bar does, the tab's own earlier Search is dropped (`dropSearches`), the search is pushed there again (same query, the result's section chip) and the result on top — so Back returns to the results, then the tab's start. **One search:** every Search screen, TV and phone, shares one query, filter chip, source, decades and genres, and tab (`SearchSession`, in memory, reset on a change of profile), and there is at most one `Search` on the back stack (`navigateToSearch` / `dropSearches`): Back never lands on a search since replaced, and a Search screen whose results are older than the shared query runs it again.

### Live TV Preview / Dock Back-Stack

Live TV always shows a channel playing alongside the browse list ([FEATURES.md](FEATURES.md#live-tv)). The Live TV section (`LiveTvTab`) is one entry and the preview is a layer on it, so Back never skips past the browse screen and out of Live TV.

- **TV** (`TvCategoryGridScreen.kt`, UX overhaul plan Part II LT7): The rail (or Home's single-section auto-skip) opens the `LiveTvTab` section — the browse entry, `showPreviewPane = false`, opened fresh on the last channel (`liveTvOpenOn`, read once; a restored section keeps its saved state and doesn't force the preview). The preview (`LiveTvSplitLayout`), with full screen promoted in place inside it, is a layer over browse: it is open while `livePreviewChannelId` (`rememberSaveable`) names the channel it opened on — the last channel on entry (no last channel: the entry opens on browse), or the channel OK was pressed on in browse. Back is a chain of stopovers in `LiveTvSplitLayout`'s `BackHandler`: full screen → preview (`fullScreen -> false`, the video keeps playing), then preview → browse (`livePreviewChannelId -> null`; the preview's player is stopped and released as it leaves composition), and only then does Back reach the nav host and pop the entry to Home. Left on the first tab stays put: only Back leaves the preview (Left did too, Live TV target item 8, until the user dropped it 2026-10-09). Browse is not composed under the preview — its rows would stay in the focus tree, and its focus effects run, behind an opaque preview or the full-screen player — so it is rebuilt on Back like a destination, its saved state (pane memories, scroll) kept in a `SaveableStateHolder`, with the same `CategoryViewModel` the preview used. The preview's own ViewModels (`PlaybackViewModel`, `StreamLoaderViewModel`) live in a store of the layer's (`LivePreviewViewModels`, held by the entry): they survive a trip to the TV Guide and back and an activity recreate, and are cleared when the layer closes, so a channel previewed for less than the watch delay is not written into Recent afterwards. **Entries opened on one channel push their own entry:** Home's Live row (with `initialCategoryId` = the virtual `favorites` or `recent`, so the context list is the one the card came from), Search (a Live TV result), the EPG Browser and the TV Guide (a channel or programme — including the guide opened from full screen's Guide button) push `CategoryList(initialCategoryId, initialStreamId)` with `showPreviewPane = true` (the default): that entry is the preview alone, with no browse layer, and Back from it pops back to the screen that opened it. After process death the layer comes back as it was: on the list it was on (kept with the screen's saved state and put back if the recreated `CategoryViewModel` lands on Recent) and on the channel last playing (`livePlayingChannelId`, saveable, cleared when the layer closes); the preview's seed waits for a list that has the channel.
- **Mobile** (`MobileCategoryListScreen.kt`): the dock and its full screen are local state (`dockTarget`, `fullScreen`), not routes. The dock seeds itself on entry — `initialStreamId` when given, else the last-played channel when the first list shown has it — so Live TV rarely opens on a bare list. Two `BackHandler`s give the stopovers: `fullScreen -> false` (full screen collapses to the dock), then `dockTarget -> null` (the dock stops and clears to the bare list). Only a third Back reaches `onBack` and leaves the screen. The toolbar's Back and TV Guide leave without those handlers, so each stops the dock first (the engine is Activity-scoped and would keep playing behind the next screen). Search, the TV Guide and the EPG Browser push their own `CategoryList` entry on the chosen channel, as on TV.

When touching either flow, keep "Back always has a real stopover before exiting" — it is why both are more than a single `navigate()` call.

**The context list (TV, `ChannelContext`, UX overhaul plan Part II LT2).** A channel carries the list it was chosen from: **the panel always opens on a list that has the playing channel** (`LiveTvSplitLayout`, checked when the channel changes, never on a tab picked by hand): when the chosen list doesn't hold it — a Live TV restored with another category selected, opened on the last channel — it switches to the channel's own category (selected in browse too, so Back lands there), else to Recent, and the channel's row takes focus; the preview layer shares browse's `CategoryViewModel`, whose selection is the *browsed* list (the real category, or the virtual `recent` / `favorites`) — not the channel's own category; an entry opened on one channel from Search or a guide has that channel's category as its `initialCategoryId` — and `LiveTvSplitLayout` turns it into a `ChannelContext` (`Category(id, name)`, `Recent`, `Favorites`; Home → Live TV is `Recent`), held in `rememberSaveable`. That one list is what the channel panel shows and what Up/Down zap through in full screen (`neighborChannel` over it) — only its channels on the playing channel's own source, in the list's order and wrapping within that source: Recent and Favourites mix the profile's sources (multi-source plan, Q4 / Phase 5). A channel picked on another source than the one playing plays through that source's `StreamLoaderViewModel` (one per source in the layer, `viewModel(key = "loader:<source>")`; the phone dock's likewise), and the loader left behind is abandoned (`StreamLoaderViewModel.abandon`) so its delayed Recent write doesn't land. The panel (`LiveTvChannelPanel`) is a `TvSectionTabs` row — the category tab, labelled with its name and present only when there is one, then Recent and Favourites, with the Refresh icon at the row's end — over a `StreamList` with no header and its rows as a `tvPane` with no neighbours: Up from the first row lands on the selected tab (the row is a focus group whose `onEnter` redirects there), Left/Right on the tabs switch the list (focus follows selection, so the context changes as focus moves) — Left on the first tab stays put and Right on the last reaches Refresh — Left/Right on a row switch to the previous / next tab too, focus staying in the rows (the new list's current channel, else its first row, scrolled into view; `PaneFocusState.focusEntryInNewList`) — Left on a row of the first tab and Right on a row of the last do nothing — and Down from the tabs enters the rows on the current channel when the list has it, else the first row. An empty tab shows a line of text and nothing focusable, so focus stays on the tab; Refresh sits at the end of the tab row, not between the tabs and the rows. None of these moves changes the channel: in the docked panel **OK on a row that isn't playing plays it in the preview, and OK on the row that is playing goes full screen** (`onStreamPromote`; sources-guide-profiles plan P8, replacing the overhaul's "preview tunes on focus"). `scripts/focus-walks/live-tv-preview.txt` walks it.

**One panel in full screen (TV, LT3).** The same `LiveTvChannelPanel` opens over the video in full screen — `PlayerScreen`'s `channelPanel` slot, filled by `LiveTvSplitLayout` — sliding in from the right at the docked panel's 34 % width: same tabs, rows, current-channel marking and row actions (long-press OK / Menu). With neither the panel nor the OSD showing, **Left and Right both open it**; it opens on the tab used last, on the playing channel's row when the list has it, else the first row (the tab row while the list loads). A remembered tab with no rows (no favourites, or the last one removed) is not reopened: the panel opens on the first tab that has the playing channel instead — the category it came from, else Recent — on its row, and that tab is the zap order from then on. Inside, the keys are the docked panel's: Left/Right on the tab row switch tabs — which switches the `ChannelContext`, so the zap order follows — Up/Down move between rows, Left/Right on a row switch tabs as in the docked panel (Left on a row of the first tab does nothing here); OK on a row tunes that channel (the same full `loadStream` on the same loader/engine as a zap) and closes the panel; focus alone never tunes in full screen. **Back closes the panel** and focus returns to the player; Right (the outward key) does not, since on the tab row it is the next tab. Focus stays inside while it is open: the panel is a focus group whose exit is cancelled while `showChannelPanel` is true (not while it animates out, so the player can take focus back), Back is taken in `PlayerScreen`'s root `onPreviewKeyEvent`, and the player's key handler leaves the D-pad and OK to it (`isModalOpen`). Up/Down/OK with the panel closed zap and open the OSD as usual. `scripts/focus-walks/live-tv-fullscreen.txt` walks it.

**The OSD (TV, `TvPlayerControlsOverlay`, LT4).** OK opens it: one row of buttons, each with its label beside the icon. Live: **Channels** (opens the same channel panel and hides the OSD; present only where there is a panel, i.e. the Live TV full screen), **Guide** (GD5: the TV Guide of the list being zapped through — the category, Recent or Favourites tab — with entry focus on the playing channel's row, via `Screen.EpgGuide(focusChannelId)`; only when the source has a guide, native EPG or an indexed one; Back from the guide returns to full screen on that channel — `LiveTvSplitLayout` keeps `fullScreen` and the channel in saved state across the round trip), ★ Favourite / Favourited, Subtitles, Audio, Quality (each only when the stream has the tracks), then **Stats** (admin only; there is no More button since 2026-10-12). VOD: the same row without Channels and Guide, with Chapters (when the file has them) before Favourite and Next episode (from 80 % of an episode that has a next one) before Stats, the row starting with **Play/Pause** (in the row since 2026-10-19, no button over the picture; there while buffering too, so the row never shifts). Focus opens on **Channels** on live — a stray second OK opens the panel, never favourites — on Play/Pause on VOD, and otherwise (live without a panel) on Stats for an admin, else Guide, else nowhere in the row — focus stays on the player, where OK does no harm; a picker returns focus to its button when it closes. Left/Right move along the row and stop at its ends (the row is a focus group whose Left/Right exit is cancelled). On live, **Up/Down still zap with the OSD up** (the OSD stays up, focus goes back to Channels on the new channel); on VOD Up from the row goes to the progress bar (Up there stays put) and Down from it back to Play/Pause. **Any key while the OSD is up restarts its 5 s auto-hide** (`controlsKeyTick`, counted in `PlayerScreen`'s root `onPreviewKeyEvent`). The live banner is in the panel above the row: LIVE · channel name (the title shows once, not again top-left), then "Now: …" with the programme's progress bar and "Next: …" when the guide has them. The resolution/codec line top-left is for an admin only (`PlayerScreenState.isDeveloperMode`, from `AppSettings.isDevMode`). The channel number goes before the name once one reaches the player. `scripts/focus-walks/live-tv-osd.txt` walks it.

**Tuning feedback and the preview column (TV, LT5).** Focus never tunes the preview (P8); OK does. From the moment a channel becomes the target — OK on another row in the preview, Up/Down or a panel pick in full screen — until the engine reaches Playing on *that* channel, `TvTuningOverlay` shows the wait ring with the channel's logo (its name when it has none; "Tuning <channel>" for screen readers), centred over a dimmed picture (in the preview pane, compact; in full screen, under the banner and the panel). The preview pane keeps Media3's default (black whenever there are no tracks). Below the preview video: channel name, its category, "Now: …" with the programme's progress and "Next: …" when the guide has them (only the target's — not the previous channel's while a retune resolves), and at the bottom one hint line, "OK  Play · OK again  Full screen · Hold OK  Options". No badge marks the layer, and no channel number yet (not in the metadata).

### TV Back on Detail Screens: intercept at `onPreviewKeyEvent`

On TV, `BackHandler` alone is **not** enough on a screen where a `Button`/`Surface` holds focus. Confirmed on a real Shield: the first Back press reaches Compose's key dispatch, but something downstream marks it handled before it reaches the `BackHandler` / `OnBackPressedDispatcher` bridge — so the press only clears focus, the D-pad goes dead, and it takes a second press to navigate. (`androidx.tv:tv-material`'s `Surface` is not the culprit — it only intercepts `DPAD_CENTER`/`ENTER`.)

`:tv`'s `MovieDetailsScreen` and `EpisodeSelectionScreen` therefore intercept Back in `onPreviewKeyEvent` on their root `LazyColumn`. Preview dispatch runs top-down, before any descendant sees the event, so it wins regardless of what swallows it further down — the same pattern `TvDpadEscape.kt` uses for the analogous Up/Down-in-a-text-field problem. The `BackHandler`s remain as an inert fallback.

Use this pattern for any new TV screen whose base state has focusable buttons and a Back action — and for overlays/panels that *replace* that root (the episode detail panel in `EpisodeSelectionScreen` intercepts on the screen's root `Box` while it is open, since the `LazyColumn` with the interceptor isn't composed then).

The player's "Up next" card (Play next episode automatically) follows it too: while the card is up over the playing episode, `PlayerScreen`'s root `onPreviewKeyEvent` takes Back — it hides the card and playback carries on, without leaving the player. While focus is in the card its buttons get the D-pad and OK; when the card is up but not focused (OSD hidden), Down moves onto it; otherwise the player's own key handling runs as usual. The card takes focus on "Play now" when it appears. On mobile a `BackHandler` hides it.

## TV Focus

Each TV screen puts focus somewhere visible when it or a panel appears and returns it to where the user was. TV-safe padding: 56dp horizontal, 32dp vertical ([design.md](design.md#safe-margins-tv-overscan)).

- **Focus is never lost for good:** when the focused control leaves the screen (removed by a state change, or a list scrolls it away) Compose clears focus and the window has none, so the D-pad did nothing until Back. `MainActivity.dispatchKeyEvent` sees a D-pad press with no focused view and gives focus back to the screen instead, entering in the key's direction (Up: the lowest control on screen), and `DeadKeyDetector.focusRestored` notes "Focus lost, given back" with the screen in Diagnostics. The episodes header's compact line stays while its Play has focus (focusing it scrolled the list back to the hero, which hid the line and the focused button: one season, Up from the first episode).

- **Back from details** (movie/series) focuses the row that was opened — `StreamList` remembers it per category (`rememberSaveable`), falling back to an item played during the visit; Live TV follows the playing channel. **A first entry opens at the top** (TV: focus on the first row; phone: unscrolled), films and shows — never on the section's last played item; TV's Live TV lists keep following the playing channel (Back from the preview lands on it), which used to put a list mid-way (Recent's newest rows out of sight). **Back from the Live TV preview** (UX overhaul plan Part II LT6) lands on the channel the preview was playing when it was left — after any retune or zap, not the row that opened it: `LiveTvSplitLayout` reports its channel each time it changes (`onPlayingChannel`), `TvCategoryGridScreen` keeps it, and when Back closes the preview layer (LT7) it hands it to browse as `returnedLiveChannelId` (`TwoColumnLayout`'s `returnedPlayingId`) — a plain `remember`, so a later return from Search or the TV Guide rebuilds browse without it. Closing the layer also refreshes the last-played item and watch state (`refreshLastPlayedItem`, `refreshWatchStateOnResume`) and reloads Recent when that is the browsed list, so a channel the preview recorded is in it. `TwoColumnLayout` then uses it in place of `lastPlayedItemId` (which only moves after the watch delay) as the items pane's selected row — so the pane remembers it and a later Right lands there too, and the row is marked current. When the list on screen does not have it (it was played from another list, or Recent has not recorded it yet), focus goes to the selected category row instead and the list does not take focus later on its own. Search / TV Guide returns use `NavReturnFocus`. `scripts/focus-walks/live-tv-back.txt` walks it.
- **Back to any other screen** focuses the control that navigated away, at the scroll position its list had — Home's header buttons and row cards; Settings' Manage Sources, Guide sources, Source stream settings, Live sync, Device info and Logs rows and its picker rows; Edit Source's Guide sources row; Search the guide's TV Guide and Guide sources buttons (Guide Sources is one page: these, Settings' row and Sources' Guide button all come back to the control that opened it); Search results; the category screen's Search and TV Guide buttons; a details screen's Start Over / Category button / related title; TV Guide programme and channel cells and its Search button (Back from "Search the Guide"); EPG Browser airing rows; Sources' Add and Guide buttons (the ⋮ menu opens dialogs only: Duplicate, Copy to…, Delete). Navigation Compose rebuilds a screen on Back with nothing focused, and Compose then focuses the first focusable (the source chip, the top Settings row). The pattern (`tv/ui/components/input/NavReturnFocus.kt`): `val returnFocus = rememberNavReturnFocus()` (saveable, so it survives the round trip); in the control's `onClick`, `returnFocus.leaveFrom(key, listState)` before navigating; `Modifier.navReturnFocusTarget(returnFocus, key)` on the control; `NavReturnFocusEffect(returnFocus, listState, fallback) { key -> /* wait for data, scroll an inner row */ }`. The effect runs when the screen is RESUMED again (after the pop transition and the screen's own first-open effects), restores the list position, then `requestFocusWithRetry` — once: the key is cleared whether or not it landed. A screen's own first-open focus checks `returnFocus.key == null` (or `isReturn`, when it can fire again after the hand-back) so it doesn't fight it. Back from the player lands on Play / the resume card, which those screens already focus.
- **Closing the episode detail panel** focuses that episode's card (the tab row if Next/Previous crossed into another season).
- **Episodes list:** Left from any episode goes to the navigation rail (Rule 6); Up from the first goes to the episodes header (the selected season tab, else Play next, else the section tabs); Right on an episode does nothing. Arrows never change season — that is the season tabs' job (UX overhaul plan Part II Phase 6).
- **Trailer player (film, show and TMDB pages):** the trailer button opens the trailer full screen in the app. The YouTube player never takes focus: OK or play/pause pauses and resumes (a pause sign shows while paused), Left and Right (or rewind and fast-forward) seek 10 seconds and show the new position ("0:22 / 1:00") for two seconds, the video's title (YouTube's oEmbed, no key) shows at the top for five seconds of play and while paused, Back closes it and focus returns to the trailer button. On the phone the player's own controls work by touch, and Back closes it.
- **Season and show watched marks (episodes screen):** hold OK or press Menu on a season tab opens a small menu (`SeasonActionsMenu`: Mark season watched / unwatched first and focused, then Cancel); closing it returns focus to that season tab. The show's mark is a `TvIconAction` in the hero's action row, between the trailer and More (label on focus; Down goes to the section tabs, as from its neighbours). Neither shows for a source that keeps watched state on its server (Jellyfin). On the phone: long-press a season chip (a dropdown anchored on it) and an icon in the action row under Play. A mark that moves Play to another episode (`anchorMovedByMark`) neither scrolls the list nor moves focus to the new "Continue Watching" card: focus stays on the season tab or the show's action.
- **TV Guide** opens on the programme on air now in the first channel that has one (separator rows are not channels) — or, opened from the player's Guide button, in the playing channel's row; Up/Down keep the time across rows, Left/Right step by programme, Up from the first row reaches the header buttons, Down from the header returns to the cell you left. OK on a channel opens its preview; OK on a programme opens its details panel (title, channel, day and time, description; Watch channel opens the preview, Close) with focus on Watch channel — or, when the channel's archive holds the programme, on **Watch from start**, first in the row (catch-up: `Screen.Player` with the archive window) — and Back or Close returns focus to the cell (GD6). Long-press OK or Menu on either cell opens the channel's row actions (below). `scripts/focus-walks/guide.txt` walks it.
- **Home (TV home overhaul plan, Phase 3):** opens on the first Continue Watching card, else the first Channels card, else the first Favourite channels card, else the first favourite movie, else the first favourite show, else the navigation rail (no section tiles since 2026-10-09). During the source's first catalogue sync, a Home with no row shows "Still loading your library…" in their place; it is not focusable, so focus goes to the rail as with no row. The rows can come after the 2 s entry wait (a profile or source switch): focus then waits up to 6 s more for one before going to the rail. Each row of cards is a `HomeRow` (`feature/contentselection/components/HomeRow.kt`): `focusRestorer` with the first card as fallback, so Up/Down into a row land on the card it had last; Left on its first card goes to the navigation rail (`leftToRail()`, outside the card's own Left cancel, so without a rail it stays put) and Right on its last cancels. Up from the first row reaches the header; Down from the header goes to the first row, on the card it had last.
- **End of a row:** Home's rows cancel Right on their last card (`focusProperties { right = FocusRequester.Cancel }`) so focus doesn't escape to the top bar. The last tab of a `TvSectionTabs` row (movie and series details, the Live TV channel panel) does the same unless the row ends in a control (`endFocusRequester` — the panel's Refresh): Right on a movie's only tab (Details) stays put instead of jumping up to Play.
- Land focus from a `LaunchedEffect` with `requestFocusWithRetry` (`tv/ui/components/input/FocusRetry.kt`): it retries each frame (about 0.5 s) on the Boolean result of `requestFocus(FocusDirection.Enter)`, then an optional `fallback`. Never `try { requestFocus() } catch (IllegalStateException)` or `runCatching`: since Compose 1.10 an unattached target logs and returns `false` instead of throwing, so those catches retry nothing (R-05). Act on the result — e.g. `StreamList` marks a Back-restore handled only when it returned true. `scripts/check-focus-retry.sh` (CI) rejects the old pattern.
- **Error states** use `TvErrorState` (`tv/ui/components/TvErrorState.kt`): focus lands on Retry on entry, Back is taken in `onPreviewKeyEvent` when the screen has one, and `RetryWhenOnline` retries once when the network comes back (R-15).

### Panes (`tvPane`)

Two-column TV screens (Live TV browse, Movies, TV Shows: `TwoColumnLayout`) are built from two panes, `tv/ui/components/input/TvPane.kt` (UX overhaul plan, Part II P1/P2), so that moves follow the layout's intent rather than Compose's geometric search (which sent Down at the end of the items into a category, and Left from a category to Search).

- `val pane = rememberPaneFocus()` per column in the screen; the list calls `pane.bind(selectedKey, firstKey, listState, indexOf)` every composition; each row's card takes `Modifier.paneItem(pane, key)`; the list's container takes `Modifier.tvPane(pane, exitLeft = …, exitRight = …)`.
- **Left/Right are taken by the pane, not by geometry:** they go to the neighbour pane named in `exitLeft` / `exitRight`, or nowhere — except a pane at the screen's left edge built with `leftToRail = true` (browse's categories column), whose Left goes through to its rows' `leftToRail()` and the navigation rail. TV Settings' group column does the same per row. **Down at the end of a pane stays put; Up at the top leaves** to whatever is above — the Refresh icon and the Search / TV Guide header buttons stay reachable from the first row.
- **Entering a pane lands on its remembered row** (the last one focused — `rememberSaveable`, so it survives Back), else the selected row, else the first; a categories pane binds with `preferSelected = true`, so Left from an item always lands on the category being browsed. A new selection (the row opened, the channel playing) becomes the memory, which is how Back from details / the player lands on the right row. A remembered row that is scrolled out of composition is scrolled to, then focused with `requestFocusWithRetry`.
- Entry focus on open: the selected category while the items load, then the items' entry row once they are there (the last played / opened item when it is in the list, else the first); an empty category keeps the category. OK on a category keeps focus on the category; Right enters its items.
- **Browse tabs** (`BrowseTabs`, the tv browse tabs plan): the virtual lists (Recent, Favourites, Wishlist, Favourite Categories, Recent Categories) are not rows of the categories pane but a `TvSectionTabs` row over the items pane (`StreamList(tabRow)`, under its title, outside its scroll), after a tab for the category last picked (`TwoColumnLayout`'s `lastPickedKey`, saveable). The categories pane holds only real categories and keeps the picked one selected (its `preferSelected` key) while a virtual list is open. Focus selects a tab, as in every TV tab row; entering the row lands on the selected tab (`focusProperties { onEnter }` before the row's `focusGroup`); Left on the first tab enters the categories pane, Down enters the items pane (an empty list: its button), Right on the last tab stays, Up reaches the header; Up from the first item, and Down from the header, land on the selected tab. While a tab has focus, a list that opens under it takes no focus, its empty state's button included (`StreamList(takeEntryFocus)`, `TvEmptyState(takeFocus)`, read once).
- **A section opened again starts on Recent:** a rail or Home pick of Live TV, Movies or TV Shows (and the rail's item of the section you are in, from one of its screens) that comes back on the section's browse sets `openOnRecent` on its root entry (`openBrowseOnRecent`, `TvNavHost`); `TvCategoryGridScreen` switches the kept `CategoryViewModel` to Recent and composes the browse only once it names Recent, so entry focus lands in Recent, and Live TV does not put its saved list back. A section that comes back on a title keeps its list, so Back lands on the row.
- Programmatic focus (`requestFocusWithRetry`, `NavReturnFocus`) passes through a pane untouched; only D-pad moves are redirected (`focusProperties { onEnter }` on the group, `onKeyEvent` for Left/Right, `onExit` + `cancelFocusChange()` for Down). `focusRestorer` is not used: it defines the same `onEnter` and the outer definition wins, and it cannot express the selected-row fallback.

The same panes build TV Settings (rail and pane), Edit Source and the TV Guide header. Edit Source's **Danger Zone** row opens its actions in place of the settings column (focus on the first; Back or Left returns to the row); on the phone it opens a full-screen page. In TV Settings a row can open a page in place of the pane's rows — a picker, Guide data maintenance, the TMDB key (`SettingPicker.TMDB_KEY`, `TmdbKeyPane`: focus on the key field, Remove key last and confirmed), or a profile's page (`SettingPicker.PROFILE`, `ProfileEditPane`): Left or Back leaves it (a profile's page with its changes, applied as they are made), with focus back on the row that opened it, or on the pane's first row after the profile was deleted. The profile page takes Left and Back in `onKeyEvent`, after the focused control, so the name's text field keeps them while it is being edited; its colour opens a picker in the same place. Your Profile (`SettingsGroup.PROFILES`) has no rows of its own: its pane is the profile in use's page with its personal rows only, for every profile, an admin too (`SettingPicker.PROFILE` shown while `picker` is null, `focusOnOpen = false` so the rail keeps focus, the name row carrying the group's `paneItem` entry key; `adminRows` false). Right or OK on the rail enters it on the name; Left and Back return to the rail row. The screen's root Back interception stands aside for it, so the name field still keeps Back. Right or OK on Admin's rail row (`SettingsGroup.adminOnly`) asks the PIN first while the session has not got it; Cancel leaves focus on the rail row. Admin's pane is one list, an item per `AdminPart` under its header; a row that leads to another part (Parental controls and a child's page) scrolls to it (`openAdminPart`). Admin → Profiles → a profile opens its page with `adminRows` true. The rail scrolls (`verticalScroll`) when a large text size makes it taller than the screen.

### Row actions (long-press OK / Menu)

A content row (a channel, title or episode in `StreamList`, a category in `CategoryList`, the Live TV channel panel's rows, a TV Guide channel or programme cell — acting on its channel) is one focus stop: OK does the row's job, and **long-press OK or the Menu key** opens its action menu (`FavoriteContextMenuDialog`: Add/Remove favourite first and focused, Mark watched on Movies (not on Jellyfin, which keeps watched state on its server) — on a show's row (TV Shows, Home's Favourite shows, Search) **Mark show watched / unwatched** instead, for all its episodes, worded once the menu knows whether every episode is watched and hidden for a source that keeps watched state on its server (Jellyfin) — Remove from Recent last, Cancel — except in a Recent list, where Remove from Recent comes first and is focused, and in Favourites, where Remove from Favourites is; `list = RowMenuList.RECENT / FAVORITES`) — UX overhaul plan Part II P3, the tv recents favorites plan. A removal is immediate (no confirmation, favourites included): focus goes to the row that took its place, else the previous row, else the list's empty state (`rowAfterChange`, `StreamList`; the TV Guide reloads its rows and does the same), and `TvUndoBar` shows "Removed X · Hold OK or press Menu to undo" for 10 s, under the list in its own room (browse, the channel panels, Home: the list shrinks while it shows; over the screen in Search and the TV Guide, where a removal takes no row away) — the Menu key or holding OK undoes while it shows (`Modifier.undoOnRemoteKeys`, for remotes without a Menu key such as the Chromecast with Google TV's; a held OK is caught on its first repeat and the rest of the press swallowed, so it neither opens the row's menu nor clicks the row, while a short OK still does the row's job), the row back in its place with focus on it. Recent and Favourites lists in browse have an edit mode (pencil in the header: OK removes the focused row, Back ends it, Recent adds Clear Recent with one confirmation; ending the mode from Clear Recent puts focus on the pencil). Home's cards (Continue Watching, Channels, Favourite channels / movies / shows, and the TMDB chart rows, whose menu has the favourite toggle and no removal) open the same menu (`HomeCardFocus.kt`): on a removal the card leaves its row, focus goes to its neighbour, else the next row's first card, else the row above, else the rail — each card keeps one `FocusRequester`, and the request is repeated once inside the row because the row's `focusRestorer` redirects a request coming from outside to the card it remembers (the removed one) or the first. A row shows a small "⋮" at its end while focused as the hint (TV Guide: on the channel cell only, programme cells being too narrow); it is not focusable. Content rows have no trailing ★ / ✓ / 🗑 buttons, so Right from a category goes straight to its items and Right from an item goes nowhere. The rule is for content rows only (P3a): rows whose few actions are the row's point, such as Sources, keep visible labelled buttons. So do guide sources: each row has its on/off switch, then Refresh / Edit / Auto-refresh / Delete under it; Auto-refresh drills into a picker in place of the list (`SettingsPickerPane`, focus on the current interval), and OK, Left or Back closes it with focus back on that row's Auto-refresh button (`epg-management.txt`). On the phone the guide source card has the same Auto-refresh button, opening a picker dialog. An episode card on the episodes screen is not a `StreamList` row: long-press OK there toggles watched (does nothing on Jellyfin). A season tab there opens its own small menu on long-press OK / Menu (mark the season watched or unwatched).

On the phone (`MobileCategoryListScreen`'s `StreamsList`) a row's actions sit behind a swipe (right: favourite, then the watched or show-watched mark where the source allows it; left in Recent or Favourites: remove), and a long press opens the same actions in `ItemActionsDialog` (`ui/components`, also Search's long-press menu): the row's title, Mark as watched / unwatched or Mark show watched / unwatched (`rowMenuActions`; none on Jellyfin), Remove from Recent in Recent, Add to / Remove from Favourites as the confirm button, Cancel. TalkBack names the long press "More actions" (`onLongClickLabel`).

### Search fields (`TvSearchField`)

A focused Compose text field opens the keyboard, and on TV the keyboard then takes every D-pad key, so the Search and EPG Browser query fields are `TvSearchField` (`tv/ui/components/input/TvSearchField.kt`, UX overhaul plan Part II P4): at rest the field is an ordinary focus stop showing the query or placeholder, so Up/Down/Left/Right move focus as anywhere else and Right reaches the clear (×) and search buttons beside it. **OK** turns it into the text field, focused, keyboard open; the IME's Search/Done action submits, **Back** closes the keyboard (submitting when the text changed), and focus comes back to the resting field. Back is taken with `onInterceptKeyBeforeSoftKeyboard` on the text field, before the keyboard can swallow it to hide itself. The editing state is hoisted: both screens open on the field without the keyboard when there are recent searches (Down reaches them) and straight into the keyboard when there are none; a return from a result uses `NavReturnFocus`. Use it for any new TV text field the user reaches with the D-pad on the way to something else. `scripts/focus-walks/search.txt` walks it.

## Adding a Screen

1. Define it in `:core:navigation`:

   ```kotlin
   @Serializable
   data class NewScreen(val someParam: String) : Screen
   ```

2. Add it to both nav hosts:

   ```kotlin
   composable<Screen.NewScreen> { backStackEntry ->
       val screen = backStackEntry.toRoute<Screen.NewScreen>()
       NewScreenComposable(
           someParam = screen.someParam,
           onBack = { navController.navigateUp() },
       )
   }
   ```

3. Navigate with `navController.navigateOnce(Screen.NewScreen(someParam = "value"))`, then add it to the tree above.
4. TV: give the screen's leftmost focusable items `Modifier.leftToRail()` (Back-Stack Rule 6) so Left reaches the navigation rail and Right comes back; a full-screen video or first-run screen calls `HideTvNavRail()` instead.
