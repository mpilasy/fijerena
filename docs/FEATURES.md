# Fijerena — Feature Reference

A native Android media player for Xtream IPTV, Jellyfin, SMB shares, local files and remote M3U playlists, on phones/tablets (`:mobile`) and Android TV (`:tv`: NVIDIA Shield, Chromecast with Google TV, Sony Bravia). This file describes what the user sees; architecture and file maps are in [design.md](design.md), screens and back-stack rules in [NAVIGATION_GUIDE.md](NAVIGATION_GUIDE.md).

---

## Sources

| Source | Live TV | Movies | TV Shows | Search | Progress sync | Auth |
|--------|---------|--------|----------|--------|---------------|------|
| **Xtream** | Yes | Yes | Yes | Local catalogue | No | Username/password |
| **Jellyfin** | No | Yes | Yes | Server-side | Yes | Username/password or Quick Connect |
| **SMB** (debug builds) | No | Yes | No | Filename | No | Optional |
| **Local** (debug builds) | With an M3U file | Yes | No | Filename | No | No |
| **Remote M3U** | Yes | Playlist entries that are video files | No | Title match | No | No |

Add Source offers SMB and Local for a new source only in debug builds (since 2026-10-24; before, for an admin): SMB can't play yet (no SMB data source) and Local has no folder picker. An existing SMB or Local source stays editable. The source type can't be changed once a source is saved.

Saving a source checks its login first. When the check fails, "Connection Failed" says why in plain words (login refused, nothing at this address, not an M3U playlist, server problem, no connection), never an HTTP code or exception text; the main action is **Go back** (focused on TV) and **Save anyway** is the secondary one. Guide errors (the TV Guide, guide source status, guide updates) read the same way.

Every text field asks for the keyboard its content needs (`FieldKeyboards`): server and guide addresses the URL keyboard without autocorrect (no space or capital after a dot), user names the email keyboard, passwords and keys the password one, names capitalised words, the guide's time offset the phone pad.

Several sources can be configured, in Settings → Admin → Sources & Guide → Manage Sources (add, edit, guide sources, copy, delete). There is no source in use: each profile has its sources (a profile's page → Sources ›), and Home, the sections, Search and the lists cover them all (see [Browsing across sources](#browsing-across-sources)). A newly added source is on for the profile in use.

**One Jellyfin login per source.** An admin signs a Jellyfin source in once, in Add Source or Edit Source, for the whole household; the login is kept with the source, like an Xtream source's password, and no profile signs in by itself. Every profile that has the source (on or off on the profile's page, as for any source) uses that one Jellyfin user, so they share its progress, watched marks and favourites, which Jellyfin keeps on its server. A source with no login yet opens Edit Source for an admin; anyone else reads "This source isn't signed in yet. Ask an admin to sign it in." On upgrade from a version with a login per profile, each Jellyfin source keeps the login of the admin profile in use, else the oldest admin's, else the most recently used profile's; the others are dropped.

**Jellyfin Quick Connect:** when adding a Jellyfin source, choose **Use Quick Connect** instead of a password. The app shows a 6-digit code to approve in Jellyfin's web UI or another client; on approval it stores the access token. No password is stored, and the token stays on the device: live sync gives the group's other devices the username only, so a source shared by several devices is best signed in with a password.

## Home

Live TV / Movies / TV Shows: on TV they are on the navigation rail (the sections of the profile's Xtream sources, merged — see [Browsing across sources](#browsing-across-sources); Live TV not when no source has channels; with a single section, Home opens it straight away on launch). Home's section tiles went 2026-10-09. TV home opens on the first Continue Watching card when there is one; with no row at all, on the rail. Under it, **Channels** (TV): the last channel watched ("Last watched"), then Recent in its own order, each once, at most 20; then **Favourite Channels**, the favourite channels in their own order. Both with "Now: <programme>" and its progress when the guide has the channel (refreshed each minute). OK opens the channel's preview; Up/Down in full screen then zap through the card's own list (Recent, or Favourites), and Back returns to Home. Hold OK / Menu on a card: Remove from Recent or Remove from Favourites (with Undo), favourite toggle. With nothing to resume, Home opens on the first channel. Then **Favourite Movies** and **Favourite Shows** (TV), the profile's favourites by name; OK opens the film's details or the show's episodes. Under each section's favourites, its **Favourite Channel Categories**, **Favourite Movie Categories** or **Favourite Show Categories** (TV; a row only when it has one): that section's favourite categories of every source, by name — a card per category (its initial over the section's colour, its name and the source badge); OK opens that section's list on the category, Back returns to the card; hold OK or Menu opens its menu, **Remove from Favourites**: the card leaves at once, focus on its neighbour, with the Undo bar (Menu puts it back). Continue watching, Channels and the favourite rows cover every Xtream source the profile has (see Recent and Favourites below): each card opens, plays and acts (menu, Undo) on its own source, carries its source's name on a badge when the profile has more than one, and takes its poster, Up next and Now line from that source. The TV backdrop is the blurred art of the card in focus (after a quarter of a second, so moving along a row doesn't flash), kept while focus is on the tiles or the header; with no card focused yet, the last-played poster. The header holds the app name (on TV the clock is at the top right of every screen, see below); then one line for all the profile's sources (there is no source in use, `docs/plans/20261012_multi-source-search-history-plan.md` → O3), over the sources that sync their catalogue: "Updating…" while one runs — "Updating 1 of 3…" with several, and once the download has counted items, its phase and running count ("Loading channels… 1 200", "Loading films… 12 400", "Loading shows… 3 100", one part at a time in that order, the number grouped the language's way, refreshed a few times a second) — else "Update failed" ("1 failed" with several), else, for an admin only, "Updated <how long ago>", the age of the least recently updated source; nothing when no source syncs (Jellyfin, M3U only). OK on it (TV; focusable only when it says something) or a tap (phone) opens **Your Sources**: each of the profile's sources with its status and, after a failed update, the reason (raw detail for an admin). During an Xtream source's first catalogue sync (none recorded yet) a TV Home with no row says "Still loading your library…" (not focusable) instead of staying blank. A profile with no Xtream source has no rows: Home says "Pick a source to browse." over a **Browse <source>** button per source; a profile with no source at all (all deleted or turned off) says "This profile has no source yet." over **Add Source** — for anyone but an admin "This profile has no source yet. Ask a grown-up to add one." and no button (focus stays on the rail). A newly added Xtream source starts that sync as soon as it is saved (before, it waited for the next scheduled sync). Then **Search the Guide** (when the guide index is ready); Search, the profile and Settings are on the navigation rail. The TV Guide grid opens from Search the guide, a category's header and the player's Guide button.

**TV Home backdrop:** behind the rows, a blurred wash of the focused card's art (a channel's logo, a title's picture), switched once focus rests on a card for a quarter of a second; a film's or show's picture also shows sharp in the top right, fading out to the left and below, crossfading from one title to the next (TV visual refresh, 2026-10-17).

**Clock.** With **Show Clock** on (Settings → Admin → This Device; this device's, off by default, not synced or exported), every screen but full-screen playback shows the time (system 12/24 h) at the top right, where the player's controls show it: on TV Home, the lists, the guide, Settings, a title's page and the Live TV preview; on the phone under the status bar, on every screen with a top bar. Full screen, picture-in-picture and the phone's Live TV dock when it covers the screen have the controls' clock only, which always shows. The clock has no panel behind it: a soft halo in the theme's background colour keeps it readable on bright art. Header buttons, the TV preview's channel list and the side card of a show's page leave its corner free; with the clock off every screen is as before. It shows for every profile on the device, a child profile's included.

**Phone Home and tabs.** A floating bottom bar (corners from Look and Feel, the tab in use in a lighter pill in the accent; screens scroll behind it and end their lists with its height, `LocalDockInset`; look in `MobileDockStyle`) has **Home** first, then a tab per section the profile's sources have (merged, as on the TV rail) — Live TV, Movies, TV Shows (Live TV only when a source has channels) — and the **profile slot**: the profile in use's avatar over its name, with a small gear badge (Settings is in its menu; the top-bar avatar of a profile with no bar has it too), whose menu switches profile, opens **Settings** and, under them, has a **Browse <source>** row per Jellyfin or M3U source of the profile (see below); the slot is lit while in Settings. On a narrow screen (under 380 dp wide, e.g. a 360 dp compact phone) the bar shows icons only, each named in a tooltip on long-press. **Home** has TV Home's rows, phone-sized, each hidden when empty: Continue watching, Channels (last watched, then Recent, with what is on now), Favourite channels, Favourite channel categories, Favourite movies, Favourite movie categories, then the TMDB chart rows **Trending Movies**, **Popular Movies** and **Top Rated Movies**, Favourite shows, Favourite show categories, then **Trending Shows**, **Popular Shows** and **Top Rated Shows** (docs/plans/20261019_phone-home-tab-plan.md). A chart row shows the chart's titles that the profile's sources have, in the chart's order, each card on its own source; it shows only with a TMDB key and the Admin switch TMDB Charts on, and never for a child (docs/plans/20261029_tmdb-charts-plan.md). The chart rows load apart from the other rows, so they never make Home slower. A long-press on a chart card opens the favourite toggle only; a card opens inside the Home tab as the lists open it (a channel docked on Live TV, zapping through Recent or Favourites), and the rows are read again on each return. Home's cards show the clean title with its tags as badges, as the lists do. An empty Recent says "What you watch shows up here." and an empty Favourites how to add one. A list icon at the start of a section's category chips opens **All Categories**: every category of the section in one list with a **Find a category** field (any part of the name), the chosen one checked; a tap opens it, as its chip would. Each section tab opens on its Recent list (newest first), Live TV docked on the last channel; the bar stays on every screen inside a tab and in Settings (not the player, Add / Edit Source or a profile's page), so each keeps its place when you switch tabs — a film's details included — and tapping the tab you're on goes back to its start from anywhere in it. The app opens on the last tab used (per profile), Home on first launch. A tab's header: the section's name (Home on Home), under it the sources' one line as on TV ("● Updated 2 hours ago" for an admin only, "● Updating 1 of 3…", "● 1 failed"; tap for **Your Sources**, each source's status and reason), then Search the guide (Home and Live TV, when the index is ready), and Search (everything on Home; on a section opened on it, with an "All Content" chip one tap away). During a source's first catalogue sync an empty list on a tab says "Still loading your library…" in place of "No films in this category". A profile with no Xtream source has no tabs, so no bar: the tab root shows a **Browse <source>** button per source (or **Add Source** with none; for anyone but an admin, "Ask a grown-up to add one" and no button), and the header keeps the profile avatar, opening the same menu. Back on a tab's start goes to Home, and on Home does nothing: Back never leaves the app (the device's Home button does). On TV, Back on Home and on the launch profile picker does nothing either.

**TV navigation rail:** faint icons down the left edge of every TV screen — your profile, Home, Live TV, Movies, TV Shows (the ones the profile's sources have), a **Browse <source>** item per Jellyfin or M3U source of the profile, Search, Settings — lit on where you are. Press Left from the leftmost item of any screen and it slides out with names; pick a section and it opens where you left it (a film's details included), pick the one you're in to go back to its start; Right comes back to where you were. Back at a section's start opens the rail, Back again goes Home. Search there searches the section you're in. Not on the player or over the Live TV preview. The first time, it slides out on its own with "Press Left for sections". See [NAVIGATION_GUIDE.md](NAVIGATION_GUIDE.md) → Back-Stack Rules.

### Browsing across sources

Live TV, Movies and TV Shows list the categories of every Xtream source the profile has in one list (`docs/plans/20261012_multi-source-search-history-plan.md` → Phase 6, part 1): by source, in the profile's order, then each source's own category order, under the virtual lists (Recent, Favourites, Favourite and Recent Categories, merged as before). With more than one source each category carries its source's name on a badge (TV rows, phone chips), and the TV header's line names the selected category's source; so do the rows of Favourite and Recent Categories, and in Recent and Favourites each row (and, in their TV guide, each channel; phone too). Badges show for an admin only. Each source keeps its own hidden categories (content filters). A category opens on its own source: its channels or titles, their stars, progress, watched checks and Now lines, its TV Guide, Refresh, and Live TV's preview, dock, zap and Start over all stay on that source. The same category id, or the same channel or title id, on two sources is two rows. Favouriting a category (or a Favourite / Recent Categories row) stars it on its own source; Favourite Categories lists every source's. The sections shown are those the profile's Xtream sources have together. A source not yet logged in lists the categories saved on the device at once and logs in behind them; one with nothing saved that doesn't answer within 15 s is left out of the list and the others still show; the section shows an error only when none of them loads (for an admin: each source's own error, raw detail included). The list marks as current the item played last across its sources, on its own source. With one source the TV header names it; with several, the selected category's (none on Recent or Favourites). Turning a source on or off on the profile's page (or adding or deleting one) shows at once in every merged list — Live TV, Movies and TV Shows with their Recent, Favourites and Recent Categories, TV Home's rows, the tabs and rail, Search, and Settings' Manage Sources — with no restart; an open list stays open while it is still there.

**Expiry banner:** Live TV, Movies and TV Shows (TV and phone, not Home, Search, details or the player) show a slim red strip under the header, above the chips or list, while one of the profile's Xtream sources expires in 7 days or fewer or has expired: a warning icon and one line per source ("panel-d expires in 5 days", "… expires tomorrow", "… expires today", "… expired 2 days ago"). It reads each source's main account expiry from its stored login answer, follows the profile's sources as they are turned on or off, and reads again when the page is opened again. On TV it is not focusable; on the phone it hides with the chips while a Live TV preview is docked.

**Jellyfin and M3U sources** stay out of the merged lists, Search and the merged history (O1): each one the profile has gets a **Browse <source>** entry — on TV a rail item below the sections, on the phone a row in the profile slot's menu. It opens that source's own section (Live TV, Movies or TV Shows) as before, scoped to it; with several, a short dialog asks which; a Jellyfin source with no login yet opens its sign-in (Edit Source) for an admin, and asks anyone else to get an admin. Back returns to where you were. With no Xtream source at all there are no merged sections: Home (TV) and the tab root (phone) show the Browse entries instead.

**Continue Watching** (Movies and TV Shows together) shows one card per show: mid-watch, its episode resumes; once an episode is finished, the card offers the first unwatched episode after it ("Up next", into the next season if needed; an episode watched in another language or quality of the show counts as watched), else the first unwatched one from the start of the show, else — every episode watched — the first episode, so a finished show stays on the shelf. It fetches the show's episode list from the source if this device never stored it (a show watched on another device). Not for Jellyfin, whose Continue Watching comes from the server. Movies show only while mid-watch.

## Live TV

Channels by category — every Xtream source's of the profile, each channel on its own source (see [Browsing across sources](#browsing-across-sources)) — plus the lists under [Virtual categories](#virtual-categories). Browsing Live TV always has a channel playing beside the list, on the same `StreamingPlaybackService` engine used for full screen, so going full screen and back never restarts the stream.

- **TV:** Live TV (on the rail) opens the preview on the last channel watched (no last channel: the browse screen); a Live TV you've already been in comes back as you left it, without restarting the video. In browse, OK on a channel opens the preview on it. In the preview, moving through the list or across its tabs never changes the channel: OK on another row plays it (the tuning ring with the channel's logo until it plays; a channel that hasn't started after 15 s is stopped and the preview says "<channel> didn't start · OK to try again"); OK on the row playing goes full screen. Below the video: channel name, category, Now / Next with progress when the guide has them, and the hint "OK Play · OK again Full screen · Hold OK Options". The channel panel beside it has tabs for the channel's category, Recent and Favourites (the list Up/Down zap through in full screen) and a Refresh button; Left/Right switch tabs from anywhere in the list, not only on the tab row; Left on the first tab stays put — Back leaves the preview. Back goes full screen → preview → browse (on the channel that was playing) → Home. Leaving the app (Home button, screensaver, HDMI input switch) pauses the preview and stops it after 30 s; coming back plays the channel again at the live edge, unless the viewer had paused it in full screen.
- **Mobile:** tapping a channel docks it in a mini-player above the list and plays it; tapping the dock goes full screen. On entry the dock starts on the channel asked for (from Search or a guide) or the last one watched. Back goes full screen → dock → bare list → out. While a channel is docked the screen rotates with the device.
- **Across the profile's sources** (docs/plans/20261012_multi-source-search-history-plan.md → Phase 5): Recent and Favourites list the channels of every Xtream source the profile has, each played from its own source (the preview, the dock and full screen switch to that source's stream when the next channel is on another one). Up/Down in full screen (TV) step only through the playing channel's own source, in the list's order, wrapping within it — another source's channels in the list are skipped; the phone's swipe zaps within the channel's source's category as before. The "last channel watched" (TV Live TV's opening channel, Home's first Channels card, the phone dock's start) is the newest of the sources' own last channels, opened on its source.

Search, the TV Guide and Search the guide open Live TV on the chosen channel; Back returns to them.

## Movies

Films by category, every Xtream source's of the profile in one list (see [Browsing across sources](#browsing-across-sources)). On the phone a film's and a show's page opens on its backdrop (TMDB's, else the poster) across the full width and up under the status bar, fading into the page, with the title's logo art (else the title, large) at its foot; the top bar is clear over it, the back button on a dark disc, and turns solid with the title once the backdrop scrolls away (TV visual refresh, 2026-10-17). Details screen: plot, cast, director, genre, rating, year, duration, video/audio tech info; the tagline above the plot, and in the Details tab the country of origin, original title (when not the title shown), original language, spoken languages and studios, from TMDB's details call (stored with the detail cache, so a cached page has them), else from the source (Jellyfin's, or the `country` an Xtream panel sends); related titles and the trailer when there is one: the source's, else TMDB's (a YouTube trailer or teaser, chosen as on the TMDB page; one `/videos` call per page with a TMDB key set). The trailer plays in the app, full screen over the page, in YouTube's embedded player (`TrailerHost`, android-youtube-player); it closes at its end or on Back. On TV the video's title (from YouTube's public oEmbed address) shows at the top for five seconds of play and while paused; a phone has YouTube's own title with its controls. When the source's trailer fails (often a video since removed from YouTube), TMDB's plays instead. With nothing left to try, a video that is gone shows "This trailer is no longer on YouTube", and one its owner keeps out of other apps opens in the YouTube app. A link that is not YouTube opens in the browser. **Play**, or **Resume from …** with **Start from Beginning** when progress is saved (from 2 % in until watched). Favourite and Watched toggles sit beside it (no Watched for Jellyfin, which keeps watched state on its server); marking watched hides the resume bar at once, unmarking re-reads it. The Details tab's **Stream name** is a menu when the title has other copies (the same TMDB id) on any of the profile's Xtream sources, each with its source's name on a badge when the profile has more than one; a copy on the same source replaces the one on screen, a copy on another source opens on that source (its details, Play, progress and favourite are that source's). It names the copy on screen as the catalogue does ("EN - Dune (2021)"), however the page was opened (Home and More like this pass the official title); after a switch, TV focus stays on it (Play if it can't take it), and the menu stays usable while the new copy loads.

## TV Shows

Shows by category, every Xtream source's of the profile in one list (see [Browsing across sources](#browsing-across-sources)). Season tabs over the episode list, opening on the season of the episode to resume, else the first season with an unwatched episode. **Play** (and the episode's "Continue Watching" badge) goes to the episode last played if it isn't finished; once it is, to the first unwatched episode after it, else the first unwatched one from the start, else the first episode. A show with episodes marked watched but nothing played opens on the first unwatched episode; marking an episode watched never counts as playing it. Episode thumbnails, per-episode metadata, resume bars; series metadata falls back to the season's. The Details tab lists the same facts as a film's, with networks for studios, plus the creators and the status with TMDB's season and episode counts. The Details tab's **Stream name** lists the show's other copies across the profile's sources, as on films.

- **Episode list caching (Xtream):** a show's episode list is stored on the device and reused until the source's catalogue shows the series changed (its `last_modified`, which panels bump when episodes are added), the viewer refreshes the show, or 30 days pass. Stored TMDB synopses are kept across those refetches, and TMDB is asked only for seasons still missing one.
- **TMDB synopses:** per-episode synopses come from TMDB when the source has none (only with a TMDB key, see Settings → TMDB key). The TMDB id comes from the series info, else from the series listing. The player's info panel shows the episode's own synopsis only — never the series' — and an episode without one has it fetched from TMDB when it starts playing.
- **Next episode:** from 80 % of an episode that has a next one (into the next season if needed), the player controls show a Next episode button (TV and mobile).
- **Play Next Episode Automatically** (per profile, switched on the profile's page in Settings → Your Profile, off by default; Xtream and Jellyfin TV shows): near the end of an episode that has a next one — the one the Next episode button plays — a small translucent "Up next" card appears in the top-right corner over the still-playing video (TV: inside the safe margins, under the clock while the controls are up; mobile: below the status bar and cutout), one line like "Up next · S1:E2 · 0:45" (minutes and seconds left) with Play now and Cancel beside it. Under it a second panel of the same width gives the next episode's own title and up to 3 lines of synopsis on TV (2 on mobile), whichever the source provided (none, no panel); on TV it shows only while focus is on the card, on mobile whenever the card shows. It appears when the time left is at most 12 % of the episode's length or 90 s, whichever is longer (5 min 38 s on a 47-minute episode, 2 min 38 s on a 22-minute one, 90 s on anything under 12½ minutes) — where the episode counts as watched (`watchedTailMs`, `WatchProgress.kt`), or straight away when playback starts or is moved inside that window; with an unknown duration it never appears early. The countdown is playback time left, so it stops with the video (paused, buffering, app in the background). **Play now** skips to the next episode at once, as Next does. **Cancel** — or Back — hides the card for this episode (it doesn't come back, even after seeking) and playback carries on; that episode then ends back on the episode list. If the episode ends with the card not cancelled, the next one plays at once (only once the app is in the foreground; a phone in picture-in-picture counts, and the card is hidden there). TV: the card takes focus on "Play now" as it appears; with the controls up both stay usable, and Down from the player reaches the card when it isn't focused. Off, with no next episode, the player leaves at the end; movies and Live TV are unaffected.
- **Mark watched** (not Jellyfin, which keeps watched state on its server): TV — long-press OK on an episode card. Mobile — tap the watched badge (filled or outline); on Jellyfin the badge only shows a watched episode.
- **Mark a season or the whole show watched / unwatched** (not Jellyfin, which keeps watched state on its server): a season — TV, hold OK or press Menu on its season tab (a menu with Mark season watched / unwatched, then Cancel); mobile, long-press its season chip. The show — an icon in the show's action row (TV: its label shows while focused; mobile: labelled under the icon), "Mark show watched", or "Mark show unwatched" once every episode is watched. The mark is written per episode for the episodes there are now, so an episode added later shows unwatched; unwatched keeps resume positions, and nothing joins Recent. Play and the "Continue Watching" badge move to the first unwatched episode at once (the season shown, the list and focus stay put); marking a single episode doesn't move them. A failure (the episode list couldn't be loaded) says so in plain words. Shows with one season have no season tabs, so only the show action.
- **Mark a show watched / unwatched from its row** (not Jellyfin): a show's row in the TV Shows lists (Recent and Favourites included), Home's Favourite shows and Search offers "Mark show watched" — "Mark show unwatched" once every episode is watched — for all its episodes, the same mark as on the episodes screen. TV: in the row's menu (hold OK or press Menu), in place of the single Mark as watched. Mobile: the watched action behind a swipe right on a TV Shows row or in its long-press menu, and the long-press menu of a show in Search. A show never opened here loads its episode list first; if that fails (offline), a message says so in plain words.

## Titles

Providers bake tags into names ("EN - Breaking Bad", "NP:Kantipur", "DE| ZDF HD", "4K-NF - …", "Breaking Bad (US)"). Lists, cards, related titles, Continue Watching, TV Home's Channels row and the player show the clean title, the tags together in one small badge ("DE · 4K · Events"; the code left out when the row's category opens with the same one, so a "BG - …" category's films don't all say BG). The Live TV preview's heading and the tuning ring's name (TV and phone) and the phone's channel toast use the clean name too: in lists and search results on the second line, before the category, year · length · rating or Now line — a channel with no guide gets a second line for them; on TV Home's narrow cards the same place, the code only; in the player before the title, on More like this posters at the top left (`parseDisplayTitle`, `TitleBadges`, `BadgedTitle`):
- **The code** before " - ", ":" or "|": "EN", "DE" (before ":" only two letters or a league, NHL, NFL, NBA, MLB, ATP, WTA, SHL, UFC, so "TRON: Legacy" stays whole), and on live channels whatever the provider writes before "|" ("IN-PREM", "UK-NOWTV", "PRIME", "HINDI"); two words for one code ("BLURAY-DE - ", "IN-TA - "); the code given twice ("EN - EN - …") once. Event lines ("Live | …") keep their status.
- **The picture format**, at the start ("4K - ", "4K| ", "PL 4K - ", "[4K-DV-HDR] - ", "4K-NF - " gives NF and 4K) or the end ("RTL HD", "Joker 4K (2019)", "(FHD HEVC)", "[UHD]", "ᵁᴴᴰ"): one badge per kind, spellings merged, the highest kept — resolution 8K, 4K (UHD, 2160p), QHD, FHD (1080p), HD (720p), SD (480p); HEVC (H265); DV, HDR; 50 / 60 fps; the provider's LQ / HQ. RAW, 3D and IMAX stay in the title.
- **Audio and subtitles** at the end, or in brackets right after the year, in the provider's words: "(FRENCH ENG-SUB)", "(MULTI SUB)", "(Ger Sub)", "VOSTFR", "(Svenskt Tal)", "[MULTI-AUDIO]", "(DUB)", "POLSKI", "DUBBING", "NAPISY", "BG-AUDIO", "Multi.Audio", "sinhronizirano"; a live timeshift "+6H".
- **The year** in brackets, wherever it is ("Dune: Part Two (2024)", "Le Retour du roi (2003) VERSION LONGUE"), with a format just before it ("Jackie Brown 4K (1997) …"): lists and search results drop it from the title and show it as plain text in the line under it (year · length · rating, before the category in Recent, Favourites and search, so a long category can't push it off), the source's own year first when it has one; the player, posters, TV Home cards and undo messages keep it in the title. Spans ("(2018-2023)") and years without brackets ("Blade Runner 2049") stay in the title.

## Search

Search across Live TV, Movies and TV Shows ("ALL", from Home) or one content type (from its category screen). At least 2 characters. Results are grouped by content type under collapsible headers, categories and items within each group; a search of everything with more than one kind of result has **type pills** (TV and phone): **All content (n)**, then each kind with its count and **Not in your sources (n)**; one narrows the results to that kind, the chosen one again (TV) or All goes back to every kind, and a new choice starts the list at its top. The choice is shared by TV and phone Search (`SearchSession.typeFilter`); recent searches show before typing (per profile). A Live TV result opens Live TV on that channel; a movie opens its details, a show its episodes. A number is also a TMDB id (Xtream sources): searching Movies or TV Shows for `9322` lists the films or shows with that TMDB id first, then the titles that contain it ("1917" still finds the film). Each word matches the start of a word in the name ("har pot" finds Harry Potter); a word in double or single quotes matches whole, and quoted words in that order (Xtream sources): `"la" land` or `'la' land` finds La La Land, not TV LAND, which `la land` also finds since "land" starts with "la". A single quote inside a word is an apostrophe ("don't").

- **Filter** (the search source filter plan, the search decade genre filter plan): a filter icon (phone: in the field; TV: under the field, OK opens a dialog) narrows the Catalogue results, in up to three sections, each choice with its count. **Source** (one choice, **All sources (n)** then each source, sorted by name): on an admin profile (as the source badges) when the results come from two or more of its sources; narrowed to one source, the results drop their source badges and "Not in your sources" is hidden. **Decade** (several choices, newest first): the year is the release date's, else the one in the name ("Dune (2021)"). **Genre** (several, the most results first): the source's genre text ("Drama, Crime"), split; the same genre in another language is another choice. Films of most providers have no genre in their list, so a genre choice leaves them out (no TMDB call fills it in). **Language** and **Region** (several each, the most results first): from the provider's code in front of the name ("EN - Dune", "GR| …", "SC-DO - …"). A language code is a language, named in the app's language (EN English, GER German); a country with one main language gives both (US English and United States, GR Greek and Greece, IR Persian and Iran); a country or region of many languages only a region (IN India, CA Canada, CH Switzerland, BE Belgium; AF Africa, EX Former Yugoslavia, LAT Latin America, AS Asia, SC Nordic countries, named by the app); any other code shows as it is under Language (NF, AMZ, D+, TOP). Channels count here too. A result matches any chosen decade, any chosen genre, any chosen language and any chosen region; with a choice made, results without that data are left out (categories always; channels under a decade or genre); "Not in your sources" titles count by year and are left out under a genre, language or region. Decade, Genre, Language and Region show for every profile, when the results have any. **Clear filters** (while one is active) clears them all (TV: and closes the dialog). While one is active the icon takes the accent colour and "Only <choices>" shows by it ("Only panel-a · 1990s · Drama · English · Greece"); the phone's type chips count what the filter leaves. The phone's menu stays open as choices are made. A result opened in another tab brings the choices along with the search. They stay until Search closes; a new query drops the decades, genres or source it has none of. It filters the results already loaded, no new search. Not on the Guide tab. The "N hidden" lines still count every source. TV: the icon ends the row of type pills; Down from the field lands on the chosen pill (the icon when there are no pills), Down from the row the results, Up from the results' top the chosen pill, Up from the row the field, Left from the first item the rail; OK on a pill keeps focus on it; the dialog opens on the first chosen row, else the first choice (never Clear filters), OK changes a row and keeps focus on it (a row stays while the dialog is open), Close or Back returns focus to the icon.
- **Catalogue and Guide tabs** (the search guide tab plan): when Search covers live channels ("ALL", or Live TV on TV) and one of the profile's sources has them, two tabs sit under the header — **Catalogue** (the search above) and **Guide** ([Search the guide](#search-the-guide-epg-browser)'s search by programme title, its freshness line, index progress, recent guide searches and results; not its header buttons or category filter). A guide result opens its channel as on Search the guide, and Back returns to the Guide tab; on the phone it opens in the Live TV tab, as a channel result does, the search brought along on its Guide tab. TV: Up from the field reaches the selected tab, Down from the tabs the field, Up from the first line of recent searches the field; choosing a tab keeps focus on it. The guide part is only loaded once the Guide tab is first shown. Search the guide itself stays, with its entry points.

- **Not in your sources** (the wanted titles plan): with a TMDB key, a search of everything, Movies or TV Shows (3 characters or more) also asks TMDB (`search/multi`, no adult titles), once typing pauses for half a second. The films and shows that no Xtream source of the profile has (same TMDB id, else the same title and year, in the app language or the original title, among rows without a TMDB id) show in their own section under the catalogue's results, at most 20, each marked with a "Not available" icon; OK or a tap opens its TMDB page (see [Wishlist](#wishlist)). Not on a child profile (TMDB is never asked), without a key, when TMDB fails (for an admin: the raw error under the heading), or when the results are narrowed to one source. TV: the section takes the first focus only when the catalogue found nothing. A search of everything gets a last type pill, **Not in your sources (n)**, while the section has titles; it shows only them, and the All pill counts them too. The typed text goes to TMDB (`PRIVACY.md`).

## Search the guide (EPG Browser)

Programme-title search across the indexed XMLTV guide, from Home's book icon (when the index is ready) or a TV Guide's Search — then with an "In <category> only" toggle (on by default) that keeps results on that guide's channels, each on its own source (a category's: its source; Recent's and Favourites': every source's). It searches the guide sources of every source of the profile in use that can have channels — Xtream and M3U (`docs/plans/20261012_multi-source-search-history-plan.md` → Phases 6 and 7). Each airing is matched to a channel of its own source; with more than one source searched it carries that source's badge, and Watch opens Live TV on that source. Airings on channels the profile can't open — excluded ones, or in a category its source hides — are left out.

- One search, by programme title (there is no channel-name mode). Only airings matched to a channel on one of the profile's sources show (there is no toggle for now).
- Results grouped by date (Today, Tomorrow, weekday, then "EEEE, MMM d"), then by programme. Every programme that hasn't ended, with no upper limit; at most 500 results per query.
- ON AIR / SOON badges; Watch opens the channel (asking first when the show airs later); Add to calendar.
- The header shows how fresh the guides searched are, across all of them (stale guide sources flagged; "Guide off: turn it on in Guide Sources" when they are all switched off, "No guide sources configured" only when there are none) and, when the profile has a source with live channels, **TV Guide** (the grid for Recent, on the first such source; Back returns to the search), a button to refresh the stale guide sources of every source searched, and **Guide Sources** (the one Guide Sources page, with no source chooser). The header names no source: the search covers them all.
- Search uses SQLite FTS4 (a raw query, then a sanitised AND-style retry). While a refresh runs, search keeps working on the previous guide: the new guide and its index are switched in together. When the index can't be used (a low-storage refresh writing straight into the guide, or an interrupted rebuild), search falls back to a slower title-only scan, flagged on screen as possibly incomplete and rerun in full once the index is ready; if even that times out, it says why ("The guide is updating…" or "The search index is being rebuilt…") and reruns by itself.
- Mobile: sticky date headers; a programme card shows up to 3 airings, the rest behind "N more airings". TV: date headers and glass programme cards.

## Guide Sources (EPG management)

Each source has its own XMLTV guide sources, all on one page (the one guide sources page plan, 2026-10-24): a group for each source on the device that can have live channels, not only the profile in use's, in the Sources list's order. A group's header is the source's name, with "Not used by this profile" when the profile in use does not have it; a source with no guide source shows "No guide sources configured" under it and, on TV, its own **Add guide source** button (that source checked in Use for); opened on that source, the TV page scrolls to it with focus on that button. Settings → Admin → Sources & Guide → Guide sources and Search the guide's Guide sources button open the page at the top, with no source chooser. Edit Source → Guide sources and Sources → a source's Guide button open it on that source's group (TV: focus on the group's first guide source, or on Add when it has none, with the group scrolled into view; phone: scrolled to the group). **Add** (one, at the top) has a **Use for** list of the sources, check boxes, shown when there are two or more: the group the page was opened on is checked, else the first; Save adds one guide source for each source checked (a source that already has that URL is skipped) and needs at least one. **Refresh stale** and **Retry failed** at the top cover every group. Add, edit and delete XMLTV URLs; turn each one on or off with the switch on its card (a guide source that is off is kept with its data but not used, searched or refreshed; for a source's own guide, `<host> (Bulk)`, the switch is the same setting as Provides a guide in Edit Source, set as the viewer's choice); refresh one, the stale or the failed ones.

- Per guide source: label and timezone offset (applied while parsing); its auto-refresh ("Refreshes daily", "Auto-refresh off"); status dot — green fresh, yellow older than the refresh interval, red error, grey disabled; download % and ingest % with channel/programme counts.
- Download to the cache directory → parse into SQLite → delete the file, on every device. Up to 3 downloads at once on mobile, 2 on TV; 2 parallel ingest workers.
- Change detection: a source unchanged since the last refresh (`304`, or the same payload hash) skips download and ingest and reads **"Unchanged"**; a hash match is overridden once a day. Truncated downloads are caught against `Content-Length` and retried.
- Retries: a refresh task retries up to 5 times (1, 2, 4, 8, 16 min); background WorkManager runs back off linearly by 10 min.
- Every programme a guide source lists is imported, however far in the past; a refresh removes the ones its new file no longer lists. A programme that runs past the next start on its channel ends there (guides list live events until a fixed cut-off over the normal schedule: panel-a had 22% of listings overlapping, NFL games 27 h long); the source's own per-channel guide gets the same rule. Search the guide names the end's day when a programme ends on another day ("18:25 – Mon 15:00"). Deleting a guide source removes its channels and programmes from the index.
- **Guide auto-refresh:** each guide source has its own interval — Off, every 6 hours, every 12 hours, daily (new ones) or weekly — shown on its row ("Off: not used, not refreshed" while the guide source is switched off) and changed with the row's **Auto-refresh** button (TV: a picker in place of the list, opening on the current value; phone: a picker dialog). On upgrade every guide source took the old device-wide setting, so nothing changed; an interval the picker doesn't offer (4, 8 or 48 hours from that setting) stays, shown as an extra checked option, until another is picked. One background job (WorkManager, run as a foreground service) runs at the shortest interval and refreshes the guide sources that are due of every source Search the guide reads (the profile in use's sources with channels), one source after another; there is no time of day and no device-wide setting (a guide source synced from an older app version, without an interval of its own, uses the old one). **Guide Data Maintenance** (Settings): Cleanup (stray files not tied to a source), Purge (programmes older than 2 days), Clear All Data (drops and recreates the index at once, keeping the guide source URLs).

Pipeline, index and search internals: [epg_guide.md](epg_guide.md), [EPG_INDEX_STORAGE.md](EPG_INDEX_STORAGE.md).

### Shared

- **In-player EPG (Live TV):** current programme with time range and progress, and the next one, fetched on start and on every zap; nothing shown without guide data.

The Live TV preview (TV) and the phone's Live TV dock show the same ring with the channel's logo while they wait. Screen readers still hear "Buffering" and "Tuning <channel>" (`WaitIndicator`, `PlayerWait`). TV and phone.
- **Stream info banner (TV):** at the start of a stream and after a channel change, the banner stays up for the whole wait (with the name at the top left when there is no logo) and hides 3 s after the picture starts. Buffering in the middle of a stream does not open it.
- **Buffering details (admin):** under the wait picture (TV and phone, not in picture-in-picture), a bar fills with the video held against what playback waits for ("1.4 / 2.5 s · 6 s": held, needed — the start amount, or the rebuffer amount after a stall — and how long this wait has lasted); then the connection in use, the measured speed, what the stream needs when it states its bitrate (amber when the speed is below it) and the server ("Ethernet · ↓ 1.2 Mbps · stream needs 4.8 Mbps · panel-a.example"). On TV Live TV the same lines sit under the tuning ring while a channel tunes (full screen; not in the preview pane). Once a load fails during the wait, a third line in amber: the failed loads, the last one's reason and what arrived ("2 errors · HTTP 503 · 3.4 MB received"). Read twice a second (`BufferingDetails`, `StreamingPlaybackService.bufferingInfo`).
- **Stalled connection:** buffering with no data at all for a minute stops with "Connection lost: no data for a minute…" and Retry, instead of retrying for 13 minutes.
- **Formats the device can't play:** a video with no decoder on the device (Dolby Vision profile 5 on most devices) or beyond it (8K on a 4K device) stops at once with "Video codec not supported on this device: <codec>", without retrying.
- **Shared logins (Xtream):** a source with extra logins (Edit Source → Logins) asks the panel, in parallel and for at most 3 s, how many streams each login has open and plays on the first free one: the one it used last, then main first (about half a second with panel-a, less on a reused connection; an answer is reused for 5 s, so Back then Play doesn't ask again). A channel change, or a new title while one is playing, keeps the login this device is playing on without asking: it replaces its own stream, so zapping is as fast as with one login. A source with only its main login asks nothing. When the panel refuses the stream as busy (HTTP 456/458/460/511), the same stream plays at once on another free login, at the same position, and the refused login is skipped on this device for 6 minutes. With none left the account-busy wait runs as before (retry every 20 s for up to 6 minutes), and its message says all N logins are in use.
- **Buffering** adapts to Wi-Fi or cellular and live or VOD at runtime without restarting the player; profiles in [design.md](design.md#buffer-strategy).

### Stats for Nerds

TV: the Stats button (admin only); a non-focusable panel in the top-right corner, so the player keeps the keys; double-OK or Back hides it. Mobile: the Stats button; closed with its X. Updated every second.

- **NAME:** the provider's raw name (and the series' raw name for an episode); for a source with extra logins, which one this stream plays on ("Login 2 of 3")
- **VIDEO:** codec, resolution, frame rate, bitrate
- **AUDIO:** codec, sample rate, channels, bitrate
- **NETWORK:** connection (Ethernet, Wi-Fi, Mobile data, VPN; Ethernet uses the Wi-Fi buffers), speed, measured bandwidth, buffer health, buffered position, rebuffer count/duration, ABR quality switches
- **PLAYBACK:** position, duration
- **PERFORMANCE:** dropped frames (<0.5 % green, <2 % yellow, ≥2 % red), drop rate
- **APP:** heap used/max (<60 % green, <85 % yellow, else red), GC count and time, UI frames skipped
- **STREAM:** type (Live/VOD), retries, stream health (live: healthy / unstable / degraded), uptime, URL
- **DEVICE:** model, API level
- **Footer:** build time and git hash, model and detected device type

## Watch State

Playback position and watched status are stored in SQLite (`watch_state`) for good; nothing is truncated. Display's Items in Recent bounds only how many cards show. Applies to Xtream, SMB, Local and Remote M3U; Jellyfin keeps this state on the server.

- **Mark watched / unwatched** (not Jellyfin) from movie details, TV episode cards (long-press OK), mobile episode badges, a whole season or show on the episodes screen, row actions (TV: long-press OK / Menu; phone: a row's swipe or long press) and search results. Marking never adds the item to Recent. Completion is sticky — a brief accidental rewatch can't clear it; only "mark unwatched" does.
- **Cross-variant dedup (TMDB):** providers carry the same title several times (language, quality, source). Watching one variant marks all of them: movies by shared `tmdbId`; TV episodes by the series' shared TMDB id, then matched on (season, episode), since each variant is a separate series and episode-level ids are almost never filled. Unmarking spreads the same way. Needs the cached catalogue, so Xtream only.

- A kid is never an admin, also when live sync or a backup restore brings a profile in: a child loses the Admin switch (the change syncs), the oldest grown-up gets it if no admin is left, and a restored file's Admin switch goes to a grown-up only. Startup also turns Admin off on a child.

- What changes the whole device (Language, Text & grid size, Items in Recent, Add a channel to Recent after, Show Clock) is an admin's only (Admin → This Device), behind its PIN, and checked in `SettingsViewModel` too. The language and Text & grid size are this device's: not per profile, not synced and not exported.

## Live Sync

Settings → Live sync. Keeps profiles, sources, each profile's sources (each source on or off on its own, so turning on different sources on two devices before they sync keeps both, and a source added on a device before it joins a group stays on), guide sources, favourites, watch progress, content filters and selected settings the same on every device of a group, through a sync server the user runs (Cloudflare Worker or self-hosted Docker image, `server/`). Everything is encrypted on the device; the server sees only keys and ciphertext. Off on a device until it is set up there. While something plays, its watch progress is sent at most once a minute (and at once on pause, stop or finish); every other change goes within a few seconds.

- **Start a sync group:** enter the server address (checked first; a setup secret if the server asks for one).
- **Add a device:** a phone scans the invite QR code a member shows; a TV, which can't scan, shows a code for a phone of the group to scan. Codes work once, for 10 minutes.
- **Manage:** last sync, Sync now, the devices list with Rename and Remove, Leave the sync group (local data stays).
- **Device names:** a device joins under its model's name ("SHIELD Android TV"). **Rename** on any row of the devices list (this device's too) names it for the whole group — every member's list, and the "Playback stopped from <device>" message. The name is a shared synced setting (`device_name:<deviceId>`), end-to-end encrypted like every record, so the server only ever knows the model's name; an empty name goes back to it. Last writer wins; a device that joins later gets the names with everything else.
- Changes reach other open devices within seconds; a closed app catches up when opened.
- **Now playing:** with **Share What's Playing with My Sync Group** on (per device, off by default, never synced), a device's row in every other member's devices list shows what it is playing and from which source — "▶ Playing · Malcolm X · 42:10 / 2:00:15 · Kid · My IPTV", "▶ Live · BBC World News — Newsday · Kid · My IPTV" (programme only when the channel has EPG), or "⏸ Paused · …". A film or episode shows its position and length; while it plays the position runs on once a second from the sender's last report (sent with each update, refreshed on the sender every 10 s), never past the end. A device on an older version sends no source, and a position that doesn't run on. Updates within seconds of a change, refreshed every 60 s while playing or paused; a device silent for 3 minutes shows as idle. Sealed like every record.
- **Remote Stop (phone app only):** a phone's devices list has **Stop** on another device's playing or paused row; after a confirmation it shows "Stopping…" until that device's line clears (or "Couldn't reach <device>" after ~90 s). The device obeys only for the playback it has on right now (a per-playback session id, never a clock), saves the watch position as Back does, closes the player for Home and shows "Playback stopped from <device>". The TV app has no Stop button. Design: the live sync now playing plan.
- Resilient by design: a record a device can't apply waits and is retried (never blocks the rest); a record the server can't accept is rejected on its own; records whose sealed timestamp or deletion flag were altered are dropped; reconnects back off; an unreadable sync link on a device resets it to unlinked rather than crashing.
- A Jellyfin source's login syncs with the source, like every source's password (sealed end to end); a Jellyfin session never does. A per-profile Jellyfin login sent by an older version becomes the source's login only when the source has none.
- Not synced: which profile a device is using, UI scale, and Jellyfin favourites and history (Jellyfin keeps those itself). The per-profile last-picked source older versions send is ignored (there is no source in use).

Design and protocol: the live sync plan.

## Settings

Settings has three entries (the admin settings plan): **Your Profile**, **Admin** and **About**. The rule: a setting of the whole household or the whole device is an Admin setting, behind the PIN; a setting of one profile is not. **An admin** sees all three. **A grown-up that is not an admin** sees only what is its own or harmless, and nothing asks a PIN: **Your Profile** (its own page: name, colour, PIN, theme, Look and Feel, play next episode automatically; and Add Profile) and **About** (version, Device info, Logs, Terms of use, Open-source licences). **A child profile has no Settings:** the TV rail has no Settings item and the phone's profile menu has no Settings row (both still switch profile), and Settings or a screen it opens, reached anyway (a restored back stack, a switch to a child while Settings is open), closes and Home opens. The Playback and Display groups are gone: their rows are on Your Profile. Adding or editing a source is the admin's only: Home asks a grown-up instead, and Add Source and Edit Source close at once for anyone else; a Jellyfin source this profile is not signed in to says "Ask an admin to sign it in" instead of opening the form (profile rules plan, PR-12). Admin is followed as it changes, so Settings shows Admin as soon as a new install makes the first profile an admin. Seven taps on the version make the profile in use an admin while no profile is one (see [Admin](#admin)). **There is always an admin:** an admin sees the Admin switch on every profile's page in Admin → Profiles, to give it or take it away, but the only admin can't turn it off (its switch is locked, with a note); and whenever no profile is an admin (an upgrade, a deletion, a sync from another device, a backup import) the oldest profile gets it back, synced (`ProfileRepository.ensureAnExpert`).

**Admin** asks the PIN of the profile in use once, on the way in (see Profile PIN), then shows one page with a header over each part, in this order: Profiles, Parental Controls, This Device, Sources & Guide, Sync & Backup; then **Shrink Database**, the last row, with no header. The rows inside ask nothing more; Your Profile and About never ask. Before the admin settings plan (2026-10-28) Settings had nine groups, and each of six Expert groups asked the PIN on its own way in. **TV:** two panes — Your Profile, Admin and About in a rail (about 30 % of the width) and the selected entry's rows beside it; the header shows the profile in use. Right or OK on Admin's rail row asks the PIN first. A row that leads to another part of Admin (Parental Controls and a child's page) scrolls Admin's page to that part, focus on its first row. Choice settings open a one-column picker in the pane, starting on the current value. **Mobile:** one scrolling list: Your Profile with a header, and under it the personal rows of the profile in use in place (no row to open; each change applies at once, the name when Settings is left), and Add Profile for a grown-up that is not an admin; then the **Admin** row (an admin only), which opens Admin's page in place of the list after the PIN (Parental Controls opens its own screen; Back or the back arrow returns to the list), then About with a header; pickers open as dialogs. Each row says what it applies to: this device, this profile, this source, or the sync group.

### Export / Import

Settings → Admin → Sync & Backup, through the system file picker.

- **Exported:** every source (name, URL, username, type, config, per-source settings with the active profile's content filters; no active flag since multi-source Phase 6 — an older file's is ignored on import; whether it is one of the active profile's sources), every guide source (with its auto-refresh interval) except an Xtream source's own `xmltv.php` guide (its address carries the login; the source's next login adds it again, and importing an older file skips it), per-source favourites, favourite categories and watch state, and global settings (the active profile's theme, Look and Feel and Admin switch; Text & grid size and the language are this device's and are not exported, an older file's text size is ignored; a file without a Look and Feel leaves it alone). The device-wide guide auto-refresh is no longer exported; importing an older file that has it turned off sets that file's guide sources to Off.
- **Not exported:** passwords (EncryptedSharedPreferences), caches, guide programme data. A hand-added guide source is exported as typed, so a password in its URL is in the file.
- **Import:** a "Select What to Import" dialog — General Settings, Sources, Guide sources, Favourites (favourites, favourite categories and watch state). Only the checked sections are imported. When an imported source's name matches an existing one: **Overwrite** (update URL, username, type, config and settings in place), **Duplicate** (add with an `(imported)` suffix) or **Skip**. Guide sources merge by URL and favourites by item id; duplicates are skipped. An added or overwritten source is turned on or off for the active profile as it was in the file's profile (a skipped one, and every source from a file older than this, leaves the profile's sources as they are). Passwords have to be entered again.

## Resilience

- **Error screens recover on their own:** a TV or mobile error shown while the device was offline (default network without `INTERNET` + `VALIDATED`, or lost) retries once when the network comes back, so a TV that starts before its Wi-Fi is up after wake recovers without a key press. An error shown while online is never retried by itself, except an account in use elsewhere (below). TV error states land focus on Retry.
- **Provider's server down:** when a stream fails with a gateway or Cloudflare status (HTTP 502–504, 520–527; 523 = Cloudflare can't reach the provider's server), the first attempt's own retries (about 45 s) run behind "Buffering…", then the player says "The provider's server isn't responding (HTTP 523). Trying again — playback starts by itself." through the next attempts, with Retry and Back; playing replaces it. Once all attempts fail: "HTTP 523 — Server unavailable. Try again shortly." (`ServerDown`).
- **Account in use on another device:** when the provider refuses a stream because the account's connections are all in use (HTTP 456, 458, 460 or 511), the player says so within seconds instead of buffering through its retries, and tries again every 20 seconds for up to 6 minutes — some providers (panel-a: 460) keep a stopped stream counted for about 5 minutes when the next one comes from a different internet address (a phone on mobile data, a device routed through a VPN), so switching devices is refused for that long; devices on the same address take over from each other at once. The message stays up through the attempts and playback starts by itself, where it would have resumed; Retry and Back work as usual. After 6 minutes it stops and asks to stop playback on the other device, then press Retry.
- **Connection slots (Xtream):** a stream nobody watches never keeps or reopens one of the provider's connections (docs/plans/20261017_xtream-stream-release-plan.md): connectivity coming back retries only a stream a screen still shows, never one that was stopped; a reconnect due while paused waits for Play; stopping or switching cancels the stream's request at once, closing a stalled socket instead of holding it until the 30 s read timeout; on the phone, stopping clears the stream from the media session, so a headset, a car or the media controls can't start it again with no screen (play/pause on the player still work); a film paused for 5 minutes stops its stream, stays Paused on screen and reopens where it was on Play.
- **Crash-loop safe mode:** when three launches within 10 minutes each end within 30 s of starting, the next launch opens a safe-mode screen instead of Home and skips the start-up work that could be the cause — EPG initialisation and auto-refresh, catalogue sync, live sync, the now-playing publisher, the start-up migrations, and the nav host's source lookups and orphan sweep. **Continue** restarts the app normally; **Clear caches** (confirmed) removes the EPG index, every source's downloaded catalogue and the poster cache, keeping sources, profiles, favourites and watch history; **Show diagnostics** opens Diagnostics. See `docs/RUN_GUIDE.md` → Crash-loop safe mode.
- **Data from a newer version:** if this device's sources were saved by a newer version of Fijerena (an older build installed over a newer one, or a newer backup restored), the app opens a screen saying so instead of crashing on every start. **Close** leaves everything as it is (install the newer version to keep using it); **Reset sources** (confirmed) sets the sources database aside as a backup and restarts with no sources, keeping favourites and watch history on the device.
