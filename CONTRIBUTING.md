# Contributing to Fijerena

The project's rules, architecture constraints and conventions. Read this before changing the code,
together with the in-depth documents in `docs/` listed below.

---

## Project Overview

Fijerena is a native Android media player built with Kotlin and Jetpack Compose. It plays content from several kinds of source (Xtream IPTV, Jellyfin, Remote M3U, and in debug builds SMB and Local files) with one app for TV (10-foot UI, D-pad) and one for mobile (touch, portrait-locked outside the player).

**Target Devices:** NVIDIA Shield, Chromecast with Google TV, Sony Bravia (Android TV), and Android phones/tablets. `minSdk` 30 (Android 11), `targetSdk` 35, `compileSdk` 37.

**App Icon:** Blue Marble (Earth) with red/cyan 3D glasses. Adaptive icon (foreground PNGs in `mobile/src/main/res/drawable-*/ic_launcher_foreground.png`, black background XML) + legacy webp mipmaps. Where each image and font comes from, and its licence, is in `README.md` → "Artwork and Fonts"; a new image or font adds its line there.

**License:** the apps are GPL-3.0-or-later (`LICENSE`), the sync server AGPL-3.0-or-later (`server/LICENSE`). A new dependency must be compatible with GPLv3 and free software (no proprietary SDKs: F-Droid rejects them).

**Sign-off (DCO):** every commit from a contributor carries a `Signed-off-by: Name <email>` line (`git commit -s`), which certifies the [Developer Certificate of Origin 1.1](DCO): the contributor wrote the change, or has the right to submit it under the project's licence. The contribution is licensed under the licence of the part it changes (GPL-3.0-or-later for the apps, AGPL-3.0-or-later for `server/`). The DCO does not give the project the right to relicense contributions; that would need a CLA.

## Tech Stack

`gradle/libs.versions.toml` is authoritative, and `README.md` → "Tech Stack" has the version table. This section gives only what the versions mean for the code:

- Sources compile to Java 21.
- Robolectric Compose tests use the v2 `createComposeRule` (`androidx.compose.ui.test.junit4.v2`): with the old rule and a dispatcher of its own, focus retries no longer run.
- Material 3 is pinned `strictly`, so the compile and runtime classpaths agree.
- `androidx.tv:tv-material` no longer brings `tv-foundation`. A selectable TV surface is `Surface(selected, onClick)` with `SelectableSurfaceDefaults` (tv-material 1.1.0 removed the toggleable one).
- Room runs on a bundled requery SQLite (FTS5 capable; the app's indexes use FTS4).
- The Jellyfin FFmpeg decoder stays on the same Media3 release as the player: no decoder is published for a later Media3 yet.
- Theming: `CinemaThemeHolder` + `CinemaThemePalette` (colour); `UiStyleHolder` + `UiStyle` (look and feel).

## Module Architecture

The module tree is in `README.md` → "Project Structure".

### Critical Architectural Constraints

1. **No Circular Dependencies:** `core:player` **must not** depend on `core:network`. If the player needs network settings, it reads directly from `SharedPreferences`.
2. **Unified Domain:** All provider-specific data must be mapped to unified domain models in `core:player/domain/` before reaching the UI.
3. **String IDs:** All media and category IDs must be `String` (not `Int`) to support diverse provider formats (UUIDs, paths, numeric IDs).
4. **Dependency Injection:** Always use `AppContainer` (in `core:ui`) to obtain repository singletons (`MediaRepository`, `ProviderRepository`). Never manually instantiate repositories in ViewModels.
5. **Async Initialization:** ViewModels must initialize repository dependencies asynchronously to prevent UI thread blocking during screen composition.
6. **Long-lived scopes:** Any scope that outlives a screen (singletons, services, repositories) comes from `AppScopes.create(name, dispatcher)` (`core:player/diagnostics`), never a bare `CoroutineScope(...)` — an exception escaping a bare scope kills the process. `AppScopes` logs it and records it in `CrashLog`.
7. **Don't swallow cancellation:** In suspend code, a `catch (e: Exception)` needs a `catch (e: CancellationException) { throw e }` before it, and `runCatching` around a suspend call is `suspendRunCatching` (`core:network`) — otherwise a cancelled job carries on and publishes stale state. `scripts/check-cancellation.sh` (CI) enforces it; mark a deliberate or non-suspend case with `// cancellation-ok: <reason>` on the catch line or the line after it (where ktlint moves it); its file allow-list (legacy files) only shrinks.
8. **Service from Compose:** In a `LaunchedEffect`/composition-scoped coroutine use `StreamingPlaybackService.awaitInstanceOrNull()`, never bare `awaitInstance()` — its `ServiceDestroyedException` escaping a composition coroutine crashes the app.
9. **`xtream_v2.db` holds user data:** every version bump needs a real `Migration`; the destructive fallback covers only pre-v7 files. See `docs/DATABASE_SCHEMA.md` §3 and "Schema Changes" below.
10. **Secrets never fall back to plaintext:** an encrypted store that can't be opened is reset (`CredentialStoreHealth.markLost`) and, if it still can't be created, replaced by `CredentialStoreHealth.InMemoryPrefs` — never `getSharedPreferences`.
11. **Startup work that could crash sits behind `SafeMode.isActive`** (`core:player/diagnostics`): `FijerenaApplication.startBackgroundWork()` and the nav hosts' `initializeStartup()` don't run in crash-loop safe mode, nor when `ProvidersDbGuard.isBlocked` (a `providers.db` from a newer build, which nothing may open). New startup work goes inside them, not around them. See the next level rock solid resilience plan → R-10.
12. **No destructive self-healing:** code that runs by itself (startup, workers, sync) never deletes user data (`watch_state`, `favorite_state`, `sync_*`, providers, profiles, credentials) by inference. Only an explicit user action or a received tombstone may. See the next level rock solid resilience plan → R-02.
13. **ViewModel coroutines use `launchGuarded`** (`core:ui/utils/LaunchGuarded.kt`), never a bare `viewModelScope.launch`: it rethrows cancellation, records the failure in `CrashLog` and passes it to `onError`, which sets the screen's error state. An init that builds a repository surfaces its failure and is retryable — never a crash or a deferred left hanging. `scripts/check-viewmodel-launch.sh` (CI) enforces it; mark a deliberate bare launch `// launch-ok: <reason>`; its per-file allow-list only shrinks. Values received from live sync (`AppSettings.applyRemoteSetting`) are validated before they're stored.
14. **An `init` block comes after the properties:** Kotlin sets properties and runs `init` blocks in the order they are written, so an `init` that starts a coroutine or collects a flow can read a property declared below it while it is still null. Whether that crashes depends on timing: it passed on a local run and failed on CI. Declare every property with a value or a delegate above the class's first `init` block (an `init` that only calls `require` or `check` may come first). `scripts/check-init-order.py` (CI) enforces it.
15. **State after a suspend call:** change screen state with `_state.update { }`, and change only the item the call was for. Never write back a copy read before the call. A load that a newer one replaces runs in one cancellable job and reads its ids into locals when it starts.

## UI & Coding Standards

### 1. STRICT: No Hardcoded UI Values

Every color, dimension, spacing, and animation duration **must** come from design token constants. Never use raw literals like `16.dp` or `Color.White`.

- **Shared Tokens (core/ui):** `CinemaAlpha`, `CinemaAnimation`, `CinemaCornerRadius`, `CinemaSpacing`; look-and-feel tokens from `LocalUiStyle` (`UiStyle.kt`).
- **Spacing follows the Look:** each `CinemaSpacing` step (and mobile `Spacing`) is its base step times the Look and Feel's density, `UiStyle.spacing` (Sharp and Console 0.9, Grotesk 0.95, Rounded and Spotlight 1.05, Soft, Meadow and Calm 1.1, the others 1.0), through `LocalSpacingScale`, which only the phone's theme provides. The steps are composable getters: code outside composition (a shape, a drawing or layout lambda, a top-level value, a style object) uses `CinemaSpacing.Base`, or reads the step into a value first in the composable. TV `Spacing` keeps the base steps in every Look: TV layouts have fixed sizes. The `Cinema*` colour values in `CinemaColors.kt` (`CinemaAccent`, `CinemaSurface`, … read from `CinemaThemeHolder`) are for theme files only: feature and component code reads `CinemaTheme` roles (the design-system gate counts a direct read).
- **TV Tokens:** `TvDimensions`, `TvFocusTokens`.
- **Mobile Tokens:** `MobileDimensions`.
- **Platform re-exports:** TV `CinemaColors.kt`/`Spacing.kt`, mobile `Color.kt`/`Spacing.kt`.
- **Colours:** `CinemaTheme.colors` roles (see Design system below), never `MaterialTheme.colorScheme` in feature code.
- **Design system (STRICT):** every look comes from two inputs — the colour theme (`CinemaThemePalette`) and the Look and Feel (`UiStyle`) — through `CinemaTheme` (core/ui `theme/CinemaTheme.kt`: colour, text, shape and border roles), then one style class per kind of element (`ButtonStyle` + `TvButtonStyle` / `PhoneButtonStyle`, and the others as the design system plan adds them), then components. Feature code uses components and roles only: no colour, `.dp` / `.sp`, `FontWeight`, corner shape, raw Material control or `MaterialTheme.colorScheme` of its own; no alpha number (`alpha = 0.5f`: use a `CinemaAlpha` token) and no type value set in place (`fontSize =`, `fontSize *`, `FontFamily.`: use a `TextRole`, `CinemaCodeText` for machine text, `ProfileAvatar(initialRole = …)` for an initial). A new kind of element gets a style class and a component first. `scripts/check-design-system.sh` (CI) holds every file to its allow-list count, which only goes down.
- **Buttons:** every button looks as its app's style says: `ButtonStyle` (core/ui, shared look) with `TvButtonStyle` (tv) and `PhoneButtonStyle` (mobile). Use the components — TV `CinemaPrimaryButton` / `CinemaSecondaryButton` / `CinemaDangerButton` / `CinemaButton(kind)`, a stack in `CinemaButtonArea`, `CinemaIconButton`, `TvIconAction`; phone `CinemaDialogActionButton(kind)` and the `CinemaButton` family — and pick a `ButtonKind` (Main, Other, Danger). Never pass colours, shapes or borders to a button, and never use a raw Material button: a change to how buttons look goes in the style.
- **Phone top bars:** every phone screen uses `MobileScreenHeader` (title, short subtitle, Back, icon actions; `HeaderGround` for a page with artwork under the bar), never a raw `TopAppBar` or `TopAppBarDefaults`. The Look and Feel sets its look (`UiStyle.topBar`: height, title role, title in the middle or at the start, fill, line); a title in the middle is in the middle of the screen while it fits between Back and the actions. A page gives its title as text (`title`, `subtitle`: a category or a count goes in the subtitle, so the title stays short); the content form is for a tab root only (`MobileSourceTopBar`). The design-system gate counts a raw top bar and fails the content form anywhere else.
- **Panels, rows and focus fills come from components:** feature code never calls a raw `Surface(` or `ListItem(`, and never sets a fill or an outline with `.background(` / `.border(`. A plain panel is `CinemaPanel` or `Modifier.panel(PanelFill, PanelCorner)` (core/ui `components/CinemaPanel.kt`; `panelOutline(PanelOutline)` for an outline): the screen names what the panel is for (`Ground`, `Surface`, `Media`, `Notice`, `DialogScrim`, …), and the theme and the Look and Feel give its colour and corner. On TV a full-screen panel is `TvPanel`; a focusable row or card is `TvCard` with a look from `TvCardLooks` (`listRow`, `infoBlock`, `avatar`, `swatch`, …), and a focus fill or outline is a focus modifier (`pickerFocus`, `accentFocusOutline`, `rowFocusOutline`, `tabChipFill` in `FocusModifiers.kt`). On the phone a preference row is `SettingsListRow`, a row of an action menu or of a list over video is `CinemaChoiceRow`, a choice or a toggle is a toggle row (the choice and toggle rows rule), any other tappable row is `CinemaRow` (mobile `ui/components`: full width, a touch target high, tap and long press; `CinemaRowDefaults.inPanel()` in a panel that pads its sides), and a card row is `CinemaCard(onClick)` or `CinemaCard(onClick, onLongClick)`. Feature code never makes a row tappable with a raw `.clickable`, `.combinedClickable`, `.toggleable` or `.selectable`: the gate counts them outside `ui/components`; a tap target that is not a row (a whole-screen tap catcher, a guide cell, a dock tab, a picker that opens its list) is marked `// look-ok: <reason>`. A new kind of panel or focus look gets a `PanelFill`, a `TvCardLooks` look or a focus modifier first. The design-system gate counts these calls outside the component folders.
- **Film and show lists stay rows:** on both apps, the Movies and TV Shows lists are rows, never a poster grid. Poster cards are only for the phone's Home rows, an actor's rows and More Like This.
- **Choice and toggle rows, one shape on both apps:** a row with a check box, a radio or a switch is a toggle row, and the whole row takes the tap (TV: one focus stop, OK toggles): phone `CinemaCheckRow`, `CinemaRadioRow`, `CinemaSwitchRow` (`ui/components/CinemaToggleRows.kt`), TV `TvCheckRow`, `TvRadioRow`, `TvSwitchRow` (`TvToggleRows.kt`). Each takes its label, optional supporting text, optional icon and `enabled` as data; the row gives the text roles (the label Body, Heading only with `labelIsName`, a source's or a Look's name; a TV switch row Heading, as the Settings rows round it). Several choices are check rows; **one choice is radio rows**, on both apps: every picker (`SettingsPickerDialog`, `TvPickerDialog`, the TV Settings picker pane), the source chooser, the search filter's source and the player's audio, subtitle and quality lists. `TvRadioRow` is the TV's one single-choice row (`TvOptionRow` is retired). A row's mark follows what is active, never focus. `CinemaChoiceRow` is for action-menu rows (`CinemaActionMenu`) and lists over video (the player's channel list, `overMedia`), never for a picker; it takes `label`, `icon`, `supportingText`, `selected` and `removal` as data, never content, so the row sets its own padding and roles. A page gives a row its inset through `modifier`; the row sets no side padding. A card's own switch (a guide source's card) may stay, marked `// look-ok: card control: <what it does>`. The design-system gate fails on `CinemaCheckbox(` / `CinemaRadioButton(` / `CinemaSwitch(` outside the components, on `TvOptionRow(`, and on a `CinemaChoiceRow(` given a content lambda.
- **Phone page actions:** several buttons for a page are a `CinemaButtonStack` (mobile `ui/components/buttons`: full-width buttons of the same size, one Main), the phone side of TV's `CinemaButtonArea`; an occasional page action (refresh stale, retry failed) is an `IconAction` in the `MobileScreenHeader`. Never a grid of buttons of different widths.
- **Settings rows say what they do, the same on both apps:** a row takes a `SettingsRowKind` (core/ui): `Navigation` (it opens a page, a picker or a dialog to choose in) ends with the chevron (›); `Action` (it runs at once, after a confirm, or only shows a value: Refresh Ranking, Export, Shrink Database) has none. Phone `SettingsListRow(kind = …)`, TV `SettingsRow(kind = …)`; the design gate fails an empty `trailing = {}` used to hide the chevron. Heavy maintenance (Shrink Database, Clear all guide data) asks first (rule 7).
- **Row actions on Settings lists, the same on both apps:** the icons go Refresh, Edit, Auto-refresh (`CinemaIcons.Schedule`), Delete, each list showing the ones it needs, in that order; a delete or bin icon has `TextTone.Danger`.
- **Phone lists end clear of the bottom bar:** every phone page's scrolling list ends with `LocalDockInset.current` of space (`contentPadding` bottom, or the last padding of a scrolled column). The design-system gate fails a phone page (a file with `MobileScreenHeader(` and a lazy list or `verticalScroll(`) that does not read `LocalDockInset`; mark a scroll that is not under the bar (a sheet's text) with `// dock-ok: <reason>`.
- **Headings over groups, the same on both apps:** a heading over a group of items in a list (Search's sections, Recent Searches) is core/ui `SectionHeader(title, count, trailing)` (`TextRole.Heading` with emphasis, the count in the secondary tone, a fold arrow or a clear action as `trailing`); a header that folds its group puts it in its own tappable (`CinemaRow`) or focusable (`TvCard`) container. The name of a small group of rows in a panel, a dialog or a filter (the filter's Source and Type, the player statistics' groups) is `GroupHeading` (`TextRole.Label` with emphasis). Do not pick a text role for these in a screen.
- **Other phone controls through components:** pull to refresh is `CinemaPullToRefresh`, a tooltip `CinemaTooltip` (`IconAction` has one already), the player's scrubber `CinemaSlider`, a search bar `CinemaSearchField` (every search screen and tab, the Guide tab too). The gate counts a raw `Icon(`, `Slider(`, `PullToRefreshBox(` or `TooltipBox(` outside `ui/components`.
- **Dialogs take their actions as data:** use the app's own `CinemaAlertDialog` (`ui/components`, never the core one) and give `main`, `others`, `danger` and `cancel` as `DialogAction(label) { … }`. The dialog gives each one its `ButtonKind`, and the Look and Feel lays them out (`UiDialogTokens.actions`: a row or a stack, label or full width, where Cancel goes; TV dialogs stay centred, D3). Never lay out dialog buttons in a screen: `scripts/check-design-system.sh` fails on `confirmButton =` / `dismissButton =`. TV focus opens on the main action, or on Cancel when there is a Danger action; a dialog whose content is a list of options passes `initialFocus` on its first item and keeps only its bottom buttons as actions. A form (a body with a field) opens on its first field, never on Cancel or a disabled Save: the field component claims the dialog's `DialogFirstField` (core `CinemaAlertDialog.kt`, `claimFirstField()`; TV `ReadOnlyFieldWithEdit` does it), so a screen does nothing. A TV form's text entry is `ReadOnlyFieldWithEdit` (a value row with a pencil, OK opens the keyboard), with a note under it where the field needs one; never a raw outlined field. An icon action (`TvIconAction`) goes in the dialog's content, not in its actions.
- **Dialog titles, colours and body:** a dialog's `title` is a string; the dialog gives it its role (Title). Only a title that needs more than text (the PIN pad's) uses `header`. A dialog takes its colours from the theme (TV: the surface behind, the text colours on it); never pass `containerColor`, `titleContentColor` or `textContentColor`. The gap between the parts of a dialog's body (menu rows, list rows, a field and its note) is `CinemaSpacing.dialogBody` (the Look's `UiDialogTokens.bodyGap`). No button in a dialog's body: its buttons are its actions. A form's own inline control (an "Add rule" in the category filter) may stay, marked `// look-ok: form control: <what it does>` on its line. Buttons that do not fit in a row of a Look of rows become a stack of full-width buttons. A centred dialog keeps a safe margin above and below, and a tall body scrolls. The cancel action is **Close** in a dialog with nothing to cancel (it shows a state, or applies each change at once: a filter, a status list, guide maintenance) and **Cancel** where it drops a choice or an action (a confirm, a form, a picker, an action menu).
- **Action menus, one shape on both apps:** every menu of actions (a row's long-press or Menu-key menu, a More or ⋮ menu, a season's menu, a "Browse <source>" menu) is the phone's `CinemaActionMenu` or the TV's `TvActionMenu`, given a title and a list of `MenuAction(icon, label, removal, onClick)` (core/ui). Each row has its icon and label in the text colour, a removal's in the danger colour; the removals go last, just above Cancel, whatever their place in the list; Cancel is the dialog's cancel button, never a row; every action closes the menu. TV focus opens on the first safe action, or on Cancel when there are only removals (rule 7). The phone's `ItemActionsDialog` adds the favourite action to a `CinemaActionMenu`; the TV's `FavoriteContextMenuDialog` does the same for a row. One choice from a list is a picker dialog (phone `SettingsPickerDialog`, TV `TvPickerDialog`), never a drop-down. The design-system gate fails on a raw `DropdownMenu` / `ExposedDropdownMenu`, a button in a dialog's body, a colour given to a dialog and a Cancel row.
- **Sheets and panels through the components:** a phone sheet (a list or a detail over the screen) is `CinemaSheet` (mobile `ui/components`); the Look and Feel decides if it opens from the bottom, as a centred panel or full screen (`UiDialogTokens.sheet`). A dialog, even a big form, is the app's `CinemaAlertDialog` (`wide = true` on TV for a big panel). A TV picker over the player is `TvOverlayPanel`, in the screen's own tree (it traps focus and closes on Back). `CinemaSheet` owns its content padding (the side margin and a gap at the bottom): callers add none. A sheet of full-width rows that pad their own sides gives `rows = true` and puts its title in `CinemaSheetHeader`. Never call `ModalBottomSheet`, `Dialog(`, `BasicAlertDialog` or `DialogProperties(` in a screen: the design-system gate counts them outside the dialog and sheet components.

### 2. D-Pad & Focus (TV)

Every interactive `@Composable` must be D-pad navigable, and every TV screen follows the focus contract (UX overhaul plan, Part I Part B and Part II; the per-screen behaviour is in `docs/NAVIGATION_GUIDE.md` → "TV Navigation"):

1. **One focus stop per row**; OK does the row's one job. Rows that need several visible actions (Settings' Sources, guide sources) use labelled trailing buttons in fixed-width slots, so Up/Down keep the column.
2. **No 2-D grids in Settings**; options are vertical lists.
3. **Up/Down never skip content:** a block that shows information is focusable or sits inside a focusable row.
4. **Left goes back one level** (pane → rail, picker → row); Right only reaches a row's trailing slots. Exception: a tab row (the Live TV channel panel, browse's tabs over the items) uses Left/Right for its tabs; Back leaves the panel, and Left on browse's first tab goes to the categories.
5. **Entry focus is the useful item:** the current value in a picker, the first row on Sources, the first action (never Cancel) in a menu.
6. **Back restores the exact control** that opened the screen, at the same scroll position.
7. **Destructive actions are never the first or default focus**, and always confirm. Removing one row is the exception (immediate, with Undo, see Row actions); clearing a whole list (Clear Recent, the recent searches of Search and Search the Guide) asks once, with Cancel focused (`ClearSearchHistoryDialog` on both apps), and focus then goes to the screen's search field.
8. **The focused control never disappears under focus:** a control that hides on a scroll or state change must stay while it has focus (`EpisodeSelectionScreen`'s compact header keeps itself while its Play is focused), or hand focus on first. When focus is lost anyway, `MainActivity.dispatchKeyEvent` gives it back on the next D-pad press (in that press's direction) and notes "Focus lost, given back" with the screen in Logs — an entry there is a bug to fix on that screen.

The primitives (all in `tv/.../ui/components/input/`):

- **Land focus with `requestFocusWithRetry`** (`FocusRetry.kt`) from a `LaunchedEffect`, never `try { requestFocus() } catch (IllegalStateException)` or `runCatching`: since Compose 1.10 an unattached requester returns `false` instead of throwing, so those catches retry nothing. Act on its Boolean result and pass a `fallback` when there is an obvious second target. `scripts/check-focus-retry.sh` (CI) enforces it.
- **Back returns focus (`NavReturnFocus.kt`):** every control that navigates to another destination records itself — `returnFocus.leaveFrom(key, listState)` before navigating, `Modifier.navReturnFocusTarget(returnFocus, key)` on the control, one `NavReturnFocusEffect` per screen (`val returnFocus = rememberNavReturnFocus()`). A screen's own first-open focus effect skips while `returnFocus.key != null` (or `isReturn`).
- **Two-column screens use `tvPane`** (`TvPane.kt`): one `rememberPaneFocus()` per column, `pane.bind(...)` in the list, `Modifier.tvPane(pane, exitLeft/exitRight = neighbour)` on the column, `Modifier.paneItem(pane, key)` on each row. Never leave a column switch to Compose's geometric search, and don't add `focusRestorer` to a pane (its `onEnter` overrides the pane's) — see `docs/NAVIGATION_GUIDE.md` → "Panes (`tvPane`)".
- **Row actions:** a content row (channel, title or category in the lists, the Live TV panel's rows, a TV Guide cell) is one focus stop; **long-press OK or the Menu key** opens its action menu (`FavoriteContextMenuDialog`, a `TvActionMenu`), and a non-focusable "⋮" on the focused row is the hint; Home's cards too. The menu opens on its first safe action; the removals (Remove from Favourites, Remove from Recent) come last, just above the Cancel button, in every list (rule 7; with only removals, Cancel has focus). A removal is immediate, no confirmation: focus goes to the row that took its place (never nothing — `rowAfterChange` / `cardAfterChange`), and `TvUndoBar` offers Undo for 10 s, in its own room under the list: the Menu key or holding OK (remotes without Menu), both previewed on the screen root by `undoOnRemoteKeys`, so while the bar shows a held OK undoes instead of opening the row's menu. No hidden trailing ★ / ✓ / 🗑 buttons on content rows. Settings' Sources rows keep their visible buttons. See `docs/NAVIGATION_GUIDE.md` → "Row actions".
- **Every text field names its keyboard with `FieldKeyboards`** (core/ui `FieldKeyboards.kt`): `Url`, `Username`, `Password`, `Name`, `Code`, `SignedNumber`. A field left on the default text keyboard gets autocorrect, capitals and a space after each dot.
- **A kept error is a code, not text:** an error stored in a database column or a preference (a guide source's `last_error`, a source's `lastSyncError`) is `StoredError(...).encode()` (core:network, `StoredError.kt`: an `ErrorKind`, plus the masked raw text for a Nerd). Show it with `storedErrorText` (core:ui) or `StoredError.message` with the screen's context, so the message is in the app language in use, not in the language of the time the error occurred. An old value (message text) shows the generic message.
- **Stats and extra information are for a Nerd, not for the Admin:** source badges and Source rows, TMDB ids, stats lines, the TV player's codec line, wait details and the raw error text under a friendly message show only while the profile is a Nerd. A composable reads `LocalNerd.current` (core/ui `history/SourceBadges.kt`, provided in both `MainActivity`s from `AppSettings.observeNerdMode()`); a view model or core/network reads `AppSettings.isNerdMode` (`friendlyErrorMessage(e, context, appSettings.isNerdMode)`). The Admin flag (`isAdmin`) gates management only (the Admin sections of Settings, the PIN, navigation, the profile editor's Admin rows, quick import), plus Home's "Updated …" time. The player's Stats button is for everyone (TV and phone).
- **Raw error text shown on screen is masked:** the "[dev]" detail a Nerd sees under a friendly message passes `Redact.text` (core:player diagnostics) — `friendlyErrorMessage(e, context, includeRaw)` does it, and so do stored sync errors (`ProviderRepository.updateSyncStats`). A raw message can carry a request URL with the login and password.
- **A badge on a card uses `BadgeKind.OnCard`** (one step lighter than the card); `Neutral` is for badges on the screen's surface, where the card colour would hide it. A colour theme can give both one fill of its own (`CinemaThemePalette.badgeFill`, Indigo's yellow); the text on a badge is `TextTone.OnBadge`.
- **TV text fields reached by D-pad are `TvSearchField`** (`TvSearchField.kt`): an ordinary focus stop at rest, OK opens the keyboard, Back closes it (`onInterceptKeyBeforeSoftKeyboard`). A bare focused text field would take every D-pad key. One field look: at rest a field looks like the open field (`CinemaTextField`, which every TV field uses while it is edited): the field's corner and outline, no fill, the white focus outline of every TV row on focus (the open field keeps the accent outline while typing); its `leadingIcon` says what it does (Search, or Add for a field that adds what is typed, as Parental Controls' "Add a word"). A field in a form is `ReadOnlyFieldWithEdit` (a value row at rest, the same `CinemaTextField` when edited); never a raw Material field, not even by its full name (the gate checks `androidx.compose.material3.OutlinedTextField(` and the other controls).
- **One "current / selected" style:** `Modifier.currentIndicator(active, …)` (`TvInputDefaults.kt`) — an accent bar on the leading edge (bottom edge for tabs, `CurrentIndicatorEdge.Bottom`; the highlight colour in a theme whose accent is as white as the focus fill, `CinemaTheme.colors.currentBar`) plus `TvFocusTokens.currentText` for the title. No tint or outline on a selected row, so it never looks like a second focused one; a focused current row keeps the bar.
- **Watched actions:** a menu's or a swipe's Mark as watched is `CinemaIcons.MarkWatched` and Mark as unwatched `CinemaIcons.MarkUnwatched` on both apps (the gate checks `MenuAction`); a detail page's watched toggle keeps its state icon (outline, filled when watched). An episode row marks through its action menu (TV: hold OK or Menu; phone: long press), never a toggle on the row.
- **Tabs and chips (TV):** the components decide their text role and marker: a page's tabs (`TvSectionTabs`, the season tabs, Search's Catalogue / People / Teams / Guide as `TvSelectableButton(tab = true)`) set their label in `TvInputDefaults.tabLabelRole` with the bar on the bottom edge and one look: no fill at rest (the label alone), the white focus fill only while focused (`tabChipFill`), whatever the row (a detail page's, the season tabs, a list's, Search's); a list's tabs with icons show the icon and the label on the current and the focused tab, the icon alone on the others (the phone's season tabs the same: Heading, the current one in the text colour over an accent bar, no fill; the phone's detail tabs scroll, each as wide as its label); a filter's chips (`TvSelectableButton`) in `TvInputDefaults.chipLabelRole` with the bar on the leading edge; a name that opens a page (a film's Director, Writers) is the same chip, never selected. A chip's label takes the Look's chip label style (`UiTypeTokens.chipLabel`: Dial's spaced capitals) through `ProvideChipLabel` (core/ui), which `TvSelectableButton` and the phone's `CinemaFilterChip` and `CinemaAssistChip` call: it changes `TextRole.Label` text only, and buttons keep their case.
- **Day headings:** a day over a list of games or airings ("Today", "Saturday, 1 November 2026") is `TvDayHeading` / `MobileDayHeading` (Sports, a team or league page, Search's Teams, Search the Guide), a band behind it only while pinned. It is one step under the section headings and the game titles (`TextRole.Body` with emphasis, secondary tone), the same on both apps.
- **Source badges** show only while the profile is a Nerd (`LocalNerd`, from `observeNerdMode()`; `SourceBadge` draws nothing otherwise). Then they end the title line, on every list row, category row and Home card on both apps (`SourceBadge` after the title; a card's second line keeps the rating and its text), and in every picker or dialog row that names a source: a title's other copies, the phone's All categories list, the search filter's Source rows (`sourceFilterLabel`: the row's label is the source's name and count, "bears (64)", the badge after it), a game sheet's channel rows (the title takes the line's free width, so the badge sits at the line's end on every row). A picker row takes the source as data (`CinemaRadioRow` / `TvRadioRow` `sourceName`, the pickers' `sourceName = { … }`), never "name · source" or "source (n)" in its label.
- **Detail pages:** a film's and a show's hero offer their actions in one order, all icon actions but Play: Play or Resume (`ButtonKind.Main`), Start over, Favourite, Watched (Mark show watched on a show), Wishlist, Trailer, More (TV); the phone's icon row has the same order, with Send to TV after Trailer while a TV can take it. The show page's compact header keeps Play as `Main`.
- **Truncated text ends with "…":** a text call that sets `maxLines` sets `overflow` too (`TextOverflow.Ellipsis`, under a marquee too: `bounceMarquee` lays the text out in its own width while it rests at the start, so it shows the start and "…", and scrolls only while focused or selected); the gate checks it (`scripts/check-text-overflow.py`). A marquee is for TV focus only: on the phone (touch, no focus) a long text ends with "…" and never scrolls, not even on the playing row; the design gate fails `bounceMarquee` / `basicMarquee` under `mobile/`. Where a card has room for two lines, the title takes two (`minLines = 2`, so the cards of a row keep one height). A short name on a narrow tile (a followed team) is `CinemaWordLines`: it breaks between words only, never inside one ("Manchester" / "City").
- **Focus look** comes from `TvFocusTokens` and the active look and feel (`LocalUiStyle.current.grid`: scale 1.0-1.09). Since 2026-10-17 (TV visual refresh): a focused **button, icon button, tab or chip** turns solid white (`TvFocusTokens.focusFill` / `TvButtonStyle.focusedContainer`, the text colour) with dark content (`onFocusFill`, `TextTone.OnFocus`; the danger colour on a deleting button) and **no ring**, so its content must inherit the surface colour (no fixed `tint`; a `CinemaText` inside any button takes `TextTone.Inherit` by default through `LocalTextTone`, and the design gate fails a fixed tone there — `scripts/check-button-text-tone.py`); a focused **card** (Home shelves, related titles) lifts with the Look's scale and an accent glow (`cardFocusGlow`) and no ring, except in a Look that doesn't scale (Sharp), where `cardFocusBorder` keeps the outline (at least `minFocusBorderWidth` 2dp). Content list rows, Settings rows, inputs, TV Guide cells (`TvCardLooks.guideCell`), small choice tiles such as Sports' followed teams (`TvCardLooks.tile`), a card's own switch (`TvSwitchButton`), the rail and avatars keep the white outline; a row made of several stops (`restingRowGround`) takes the focus fill and the outline across the whole row. See `FocusModifiers.kt`. Avoid complex animations on mid-range TV chipsets (e.g., Sony Bravia).
- **Action buttons are icons** (`TvIconAction` / `CinemaIconButton` on TV; mobile `IconAction` / `CinemaIconButton`), never a raw `IconButton`: the label shows only while focused on TV, in a long-press tooltip on mobile, and is the content description; the phone's detail-page actions too (`DetailIconAction`: no caption under the icon, on the film, show, episode and TMDB title pages). Play and Resume show the play icon before their label (phone `PlayButtonLabel`, TV `CinemaPrimaryButton(icon = CinemaIcons.PlayArrow)`), never a "▶" typed into a string: the design gate fails a ▶ in strings.xml. An icon's colour is a tone (`TextTone`, from the theme): `CinemaIcon(tone = …)` (TV `TvIcon`), `IconAction(tone = …)`, `TvIconAction(iconTone = …)` — never `tint =`. The design gate counts raw `IconButton(` and `tint =` outside the icon components, and a raw `Icon(` outside `ui/components`. A delete (bin) action has `TextTone.Danger` in every list on both apps. **Add** is an icon action with the Add icon on both apps: in the page's header where the page has one (Sources, Guide Sources, Live Sync's Add a Device), else at the end of the list it adds to (logins, profiles); a field that adds what is typed stays a field ("Add a word", with the Add icon). Text stays for dialog buttons, a screen's single main action and form submits (Play, Save, Add, Retry), and setting value rows. Never turn icons into text buttons without a maintainer's decision. See the icon buttons plan.
- **Lists are plain `LazyColumn`/`LazyRow`.** Never `TvLazyColumn`/`TvLazyRow`: `tv-foundation` 1.0.0-alpha10 calls a prefetch API removed in Compose 1.9 and crashes on scroll.
- **Back on TV:** where a focused `Button`/`Surface` exists, intercept Back in `onPreviewKeyEvent` on the root — `BackHandler` misses the first press. See `docs/NAVIGATION_GUIDE.md` → "TV Back on Detail Screens".
- **In-tree overlays trap focus:** a picker drawn in the screen's own layout (not a `Dialog` window) wraps its content in `.focusProperties { onExit = { cancelFocusChange() } }.focusGroup()` (focusProperties directly before focusGroup) and refocuses its opener on close. Don't trap overlays that animate out while focused. `onExit = { FocusRequester.Cancel }` does nothing. The TV game reminder banner (`TvGameReminderBanner`) is not such an overlay: it takes the keys without moving focus (`reminderBannerKeys`, an `onPreviewKeyEvent` on the screen's content; Left / Right choose a button, drawn as focused with `highlighted`, OK acts, Back closes, every other key but volume is swallowed), so the control under it keeps focus when it closes. It is not drawn while a `Dialog` window has the window focus (`LocalWindowInfo.isWindowFocused`), so it never sits under a dialog out of reach. The send banner (`TvSendBanner`) has the same keys: a new banner of this kind takes `TvBannerKeys` and `TvBannerPanel` (`TvBanner.kt`), never a copy.
- **Loading states:** a pane that waits (a search, the guide index) shows `TvLoadingState` / `MobileLoadingState` (a spinner and one sentence, "Searching…" by default, in the empty state's place and size). `MitadyLoading` stays only for an inline status line in `TextRole.Body`; the gate fails it in a large role.
- **Error states:** TV uses `TvErrorState` (focus on Retry, auto-retry when back online) for real failures only; an empty result (no channels, no guide sources, an empty category) is `TvEmptyState` (centred sentence, optional icon and one action). Mobile uses `MobileErrorState` (Retry, auto-retry when back online through `RetryWhenOnline`, `core:ui`) for real failures and `MobileEmptyState` for an empty result. Every error state has Retry.
- **Feedback:** no `Toast`. A short plain message ("Joined", "S9E17 is not in your source") goes through `AppNotices.show(text)` (`core:ui`), from any code; each app shows it in its one host at the root of its screens: the phone's `CinemaSnackbarHost` (above the dock, the system bar and the keyboard) and the TV's `TvNoticeHost` (bottom centre, never focused). An Undo after a removal is the phone's `LocalCinemaSnackbar.current.show(name) { … }` ("Removed X · Undo", 10 s, gone when the screen changes) or the TV's `TvUndoBar`, which places itself: put it in the screen's column under the list (the list takes `Modifier.weight(1f)`), with no alignment or padding. A removal from Favourites, Recent or the Wishlist has its Undo on both apps, wherever it is made (lists, menus, Search, the category chips, the Guide). No screen draws its own `SnackbarHost`. Exception: a message for when the app can be behind another app (a remote Stop during background audio) stays a `Toast`, marked `// look-ok:`. The design-system gate checks all of this.
- **Empty states:** every "nothing here" (no results, an empty list) is `MobileEmptyState` / `TvEmptyState`, with an action only when one helps (TV Search's "Search everything" from a section's Search); never a `CinemaText` of a `*_no_results*` / `*_empty*` string built by hand (the gate checks it). One structure on both apps: an icon, the title (`message`), an optional body (`secondary`) and an optional action; a search with no results has the Search icon and the one wording ("No results found for … Try different keywords.", `search_no_results_query_format` and its kin). A TV empty state whose content changes as the user types gives `takeFocus = false`.
- **Shared TV pieces (TV UI audit, the tv ui audit plan):** a screen's header is `TvScreenHeader` (title, short subtitle, icon actions right); content list rows take their colours and focus look from `TvListRowDefaults` (light lift, white outline, text stays white; accent only for the current bar), settings / input rows from `TvInputDefaults` (same look); channel logos go through `CinemaThumbnail` with `ThumbnailContentType.LIVE_TV` (drawn whole, never cropped); provider separator rows (`#### … ####`) are non-focusable headings, never played, zapped to or counted. Text & grid size scales the whole app through `LocalDensity` at the root — don't scale sizes per screen (`.scaled()` is a no-op kept for old code).
- **Focus walks:** a change to a screen's focus order updates its Robolectric focus test (`tv/src/test`, `FocusWalk`) in the same commit, or its walk in `scripts/focus-walks/` where no test covers that move (re-record with `scripts/tv-focus-walk.sh -r`; see `docs/RUN_GUIDE.md` → "Focus walks").

Apply TV-safe margins to all root containers (56dp horizontal / 32dp vertical):

- UI should remain 5% away from screen edges.

### 4. Typography

- TV: 15-style scale (48-14sp) — Manrope for display/headline styles, Roboto (system default) for title/body/label; a Look and Feel can set its own font (`UiTypeTokens.fontFamily`, titles with `titleFontFamily`; every Look but Standard brings its own bundled font, `UiFonts`, licences in `licenses/fonts/`).
- **Rule:** All body text **>=18sp** for TV readability.
- TV images are decoded at 1080p at most (`MaxImageSizeInterceptor`, registered on leanback devices in `FijerenaApplication.newImageLoader`): a 4K Shield lays out at 3840 px.
- TV UI scale (Text & grid size: 8K / 4K / HD / SD = 40/60/80/100 %, or Auto, the default: 4K on a 4K screen, HD on 1080p, SD below, from the display's best mode — `autoUiScale`; `AppSettings.uiScaleChoice`, null = Auto) is applied globally via `LocalDensity` in TV `MainActivity.kt`.

### 5. Strings and Titles

- **Strings:** every user-visible string is a resource in a `core` module (`core/ui`, `core/network` or `core/player`, under `src/main/res/`), added to `values/`, `values-fr/` and `values-mg/` in the same change — the three files of each module carry the same keys. `tv` and `mobile` hold only `app_name`. A count with a noun ("1 category", "3 categories") is a `<plurals>` resource read with `pluralStringResource` / `getQuantityString` (or `UiText.PluralResource` from a ViewModel), never "%1$d categories" or "item(s)". Separators between parts of a line ("Updated 1d ago • 1 stale") are joined in code with a space on each side: a leading space in a resource is dropped.
- **Wording:** in the UI content providers are **sources** ("Add Source", "Manage Sources"; French *source*, feminine; Malagasy *loharano*), and EPG/XMLTV feeds are **guide sources** (*source de guide*, *loharanon'ny fitarihana*). Code keeps "provider" (`ProviderEntity`, the `providers` table, `providerId`, string keys such as `provider_add_title`), so new strings use the new words with the old key style. "Provider" stays only where it means the company that sells the IPTV service. See the provider to source rename plan.
- **One word for each thing (English):** say **film** and **show**, not "movie" and "series". One action has one name on every screen.
- **Title Case (English only):** write a screen title, a dialog title, a section or group heading and a Settings row label in Title Case ("Guide Sources", "Add a Channel to Recent After", "Delete Source?"). Write small words (a, an, the, and, or, but, of, to, in, on, at, by, for, with) in lower case when they are not the first or last word. Keep brand and technical names as they are (TMDB, PIN, Live TV). Buttons, menu items, chips, descriptions, messages, hints and values stay in sentence case. French and Malagasy keep sentence case everywhere.
- **Provider titles:** raw names carry tags (`EN - …`, `4K-NF - …`, `AFR: …`, `… (US)`). Show them through `BadgedTitle` (`core:ui`, `LanguageBadge.kt`) or `parseDisplayTitle` (`core:player/domain/TitleLanguage.kt`): the tag becomes a `LanguageBadge` beside the clean title. A category whose whole name is one tag ("en", "4k") shows as that badge on its rows too (`categoryNameAsTag`), never as plain text, in every list that names the category (the lists, Recent, Favourites, Search's results); any other category name stays plain text. A row with no title left after its tags shows the stream's raw name, else its category (`rowDisplayTitle`), before "No title". Episode names go through `episodeOwnTitle` / `playerEpisodeName` / `episodeTitleWithoutSeries` in the same file. Stats for Nerds shows the raw names on purpose.

### 6. Coding Style

- **Single return statement** per function only.
- **A parser change adds or updates a fixture:** a change to code that reads provider data (Xtream, XMLTV, M3U, Jellyfin, TMDB, sports, sync) comes with a fixture and a test that reads it. Fixtures are under `src/test/resources/fixtures/<kind>/` (Xtream in `core/player`, the others in `core/network`) and load with `fixture("<kind>/<file>")`. A `rec-<action>` file is a recorded answer, cleaned and trimmed; a `var-<action>-<quirk>` file is written by hand for one quirk, and its test names where the quirk comes from (a field report or a format document). A new file is at most 16 KB, with 3 to 5 items in a list. Tests read Xtream answers with `XtreamJson`, the client's own Json settings, never a copy. This repository is public: no login, provider host, address, token or private title goes in a fixture, and `scripts/check-fixture-privacy.sh` (CI) fails on one.
- **OS:** Ubuntu Linux development environment.
- **Lint:** `./gradlew ktlintCheck` verifies style, `./gradlew ktlintFormat` fixes it. ktlint-gradle 14.2.0 with ktlint 1.8.0 (ktlint-gradle older than 14.1 lints nothing under AGP 9). Rules are in `.editorconfig`.

## Player Implementation

### Configuration & Source

- **Source Creation:** Always use `StreamingMediaSourceFactory.createMediaSource()`.
- **Formats:** HLS (`.m3u8`), DASH (`.mpd`), MPEG-TS (`.ts`, `.mpeg`).
- **Buffer Strategy:** `AdaptiveLoadControl` dynamically swaps buffer profiles (Live TV vs VOD, WiFi vs Cellular) at runtime, from the constants in `NetworkBufferProfile` (cellular uses the profile sizes as they are; there is no user multiplier any more). VOD keeps no back buffer (ExoPlayer counts it against the byte cap; on 4K it starved the forward buffer) and its byte cap scales with the heap (`NetworkBufferProfile.vodTargetBufferBytes`, 64-160 MB).
- **Codec Priority:** Optimized per device (`DeviceCapabilities`: Shield and Chromecast with Google TV: AV1 -> HEVC -> AVC; Sony: HEVC -> AVC; others: AVC).

### Controls & Navigation

- **State Management:** `PlaybackViewModel` delegates to `StreamingPlaybackService` (a `MediaSessionService`).
- **OK / Center Key:** **Shows controls only** — it never pauses or resumes playback. On TV it opens the OSD (`TvPlayerControlsOverlay`): one row of icon buttons, each naming itself while focused, focus on Channels on live, Play/Pause on VOD.
- **Double-OK:** Dismisses the stats overlay if visible.
- **Pause:** Explicit via pause button or `KEYCODE_MEDIA_PLAY_PAUSE`. Mobile double-tap seeks, it doesn't pause — see Mobile Gestures below.
- **Seeking / Navigation:**
  - **VOD:** Use `PlaybackViewModel.seekRelative(offsetMs)` for relative position changes (FF/Rewind).
  - **TV VOD:** with controls hidden (or on the focused progress bar), a D-pad Left/Right tap jumps 10 s at once; held, it moves a scrub cursor (`stepScrubCursor`, `scrubStepMs`) that seeks on release (`commitScrub` on KeyUp) or OK. REW/FF move the same cursor; OK commits. Back cancels.
  - **TV Shows:** a Next episode button appears in the player controls (TV and mobile) once 80 % of the episode has played, and the "Up next" card offers the next episode near the end (only Watch now plays it). There is no Previous episode button.
- **Channel panel (Live TV):** TV: one `LiveTvChannelPanel` — docked in the preview, and over the video in full screen where D-pad Left or Right (or the OSD's Channels) opens it (tabs Category · Recent · Favourites, focus on the playing channel, Back closes it); the panel's list is the zap order (`ChannelContext`). Mobile: a horizontal swipe opens `MobileChannelListSheet` (category one way, Last Watched the other).
- **Live TV is one nav entry (LT7):** on TV, the Live TV section (`Screen.LiveTvTab`, from the rail) is one entry hosting browse with `showPreviewPane = false`. The preview (`LiveTvSplitLayout`) and its in-place full screen are layers over browse inside that entry, open while `livePreviewChannelId` (saveable) is set — never push a nav entry for them. Back steps full screen → preview → browse → the rail → Home. Entries that open on one channel (Search, EPG Browser, TV Guide) push their own `CategoryList` with `showPreviewPane = true` (preview only, Back returns to the opener). Mobile has one `CategoryList` entry too; its dock and full screen are local state (`dockTarget`, `fullScreen`). Both promote to full screen on the same engine connection (no restart), and Back always has a real stopover before leaving Live TV — see `docs/NAVIGATION_GUIDE.md` → "Live TV Preview / Dock Back-Stack".
- **Mobile Gestures:** `detectTapGestures` (tap=controls; double-tap=10s relative seek, VOD only — left 40% of the width rewinds, right 40% seeks forward, center 20% does nothing; while the seek pill shows, one tap on a side seeks again, `SeekTaps.kt`). A relative seek counts from `PlaybackViewModel.seekTarget` while the player has not reached it, so taps during the buffering after a seek add up. Merged `detectDragGestures` (vertical=channel switch, horizontal=channel sheets; 56 dp on either axis, a drag starting in the outer 10 % of any edge ignored — `ChannelSwipe.kt`).

### Features

- **Stats Overlay:** Opened from Stats in the player controls (on TV behind ⋮ More); double-OK or Back dismisses it. Comprehensive diagnostics (codecs, network speed, dropped frames, build info, the provider's raw names). Non-focusable on TV, so the remote keeps controlling playback.
- **Stream Info:** the resolution/codec line under the title; on TV only for a Nerd (`PlayerScreenState.isNerd`).
- **Auto-resume:** position saved every 10 s while playing; VOD always resumes from 2 % in until it is watched — inside the last 12 % of its length or 90 s, whichever is longer (`WatchProgress.kt`, core:player; no setting; Start over starts again). The Up next card appears at the same point, but at most 4 min before the end (`UpNext.kt`), and only its Watch now plays the next episode.
- **Position saves:** `StreamingPlaybackService.positionSaves` (process-wide `SharedFlow<PositionSave>`, no replay) carries every periodic, state-change, track-choice and teardown save; the player screen collects it in a composition-scoped `LaunchedEffect` and calls `loaderViewModel.recordHistory`. Never attach a callback to a service instance: it is destroyed and recreated (TV `onStop`, cold start). `releasePlayerAndSession` runs each teardown stage in its own `releaseStage`; keep new stages inside one and the singleton reset last.
- **Network deadlines:** a new request/response API call gets its client's overall deadline (Xtream metadata, Jellyfin, sync 60 s; TMDB 30 s); a bulk download opts out (`timeout { requestTimeoutMillis = INFINITE_TIMEOUT_MS }`). The player's streaming clients, EPG downloads and the sync WebSocket never get a call timeout.
- **Shared logins:** an Xtream playback URL goes through `XtreamLoginPicker.forPlayback` (`XtreamMediaProvider.resolvePlayableStream` does it), so it may carry an extra login, and a refusal can move it to another (`AlternateLogin`). Compare stream URLs with `XtreamStreamUrl.sameStream`, never `==`. See the shared logins plan.
- **Catch-up (Xtream):** a past programme plays through `Screen.Player` with the channel's archive window (`catchupStartSec` …) and `isLive = false`, so every `isLive` branch takes the VOD side; the loader skips Recent and positions for it. Which programmes replay is `CatchupAvailability.isPlayable`, one rule for every screen; the timeshift start is in the panel's clock (`XtreamPanelClock`). See the catchup plan.
- **Handing the player to another screen:** there is one player (`StreamingPlaybackService`). A screen that leaves for another that plays at once (catch-up's Back and Watch live, Start over) stops it synchronously (`StreamingPlaybackService.getInstance()?.stop()`, not `PlaybackViewModel.stop()`, whose coroutine can land after the next stream started; not `stopAndRelease()`, which ends the service the next screen starts on), then must not pause, stop or release it on its way out. `PlaybackViewModel.onCleared` stops the player only while it still plays that view model's own stream. A screen that plays on TV also registers `PlayHandoverEffect` (save, stop, mark handed off), which a Send to TV's Play calls before the next player opens.
- **Logging secrets:** anything that logs a URL or exception text that may hold credentials goes through `Redact.text` (`core:player/diagnostics`); `CrashLog.record` already redacts.
- **No passwords outside the credential store:** the automatic Xtream guide source is stored as `<server>/xmltv.php` and gets its login only for the request (`AutoXmltvSources.fetchUrl`); don't write a credentialed URL to `epg_source` or to an export. Android backup and device transfer are off (`core/ui` `data_extraction_rules.xml`). See `PRIVACY.md`, and keep it true when what the app stores or sends changes.
- **Hidden categories and exceptions:** a query or filter that hides the items of excluded categories keeps an item with `allowed = 1` (a Parental Controls exception). See the `XtreamStreamDao` KDoc.
- **Provider changes:** a change to a provider's settings, URL or login goes through `MediaProviderFactory.providerChanged(id)` (in the app) or `SyncEngine.Listener.onProvidersChanged` (from sync), which `AppContainer.onProvidersChanged` turns into dropping the cached repository and provider together. Never call `MediaProviderFactory.clearCache` alone for a config change: the cached `MediaRepository` keeps the old, disconnected provider.
- **Watch History Rules:**
  - **Live TV:** Added to history after `watchDelaySeconds` of playback with a picture (default **10 seconds**, 5-120, Settings → This Device → Add a Channel to Recent After). The delay, and the at-once write on full screen, count from the engine's first picture of that stream (`StreamingPlaybackService.engineStream`, `awaitPicture` in the loader); time without a picture does not count, and a channel that never plays never goes into Recent.
  - **VOD (Movies/Series):** Added to history only after reaching a **2% watch threshold**.
  - **Session Finalization:** `loaderViewModel.stopPlayback()` MUST be called when exiting the player or switching streams to ensure final progress is reported and history is flushed to disk.
- **Watch State Storage:** Position and completion live in the durable `watch_state` Room table (`xtream_v2.db`, added in v15), **not** in SharedPreferences — the old `watch_history_v3` blob truncated to `watchHistorySize` on every write and is now migrated and purged on first `setProvider()`. `AppSettings.recentRowSize` (Items in Recent, Settings → This Device, one value for each device) bounds the *Recent* row's length, never what is stored. Reads go through `MediaRepository`; never re-introduce a blob writer.
  - **Completion is sticky:** progress upserts do `MAX(existing, new)` on `isCompleted`. Only `setWatched(false)` (or `setEpisodesWatched(…, false)`) clears it.
  - **Manual marking:** `MediaRepository.setWatched(itemId, contentType, watched)`. No-ops for server-backed providers (Jellyfin owns that state). A manual mark leaves `lastPlayedAt` null so it never pollutes the Recent row. A season or whole show is `setEpisodesWatched(seriesId, season, watched)` (`season` null = the show): one row per episode existing now, in one transaction, so a later episode stays unwatched; `episodesWatchState` gives the toggle's wording.
  - **TMDB dedup:** movies join `xtream_streams` on shared `tmdbId`; episodes join `xtream_series` on **series-level** `tmdbId`, then match `(season, episodeNum)` — episode-level `tmdbId` is effectively never populated by providers and must not be used for this.
  - **Track prefs:** `audioTrackIndex`/`subtitleTrackIndex` persist per row, with a series-level fallback so a new episode inherits the last choice made in that series.

## EPG & Indexing System

- **Pipeline:** `EpgFileManager` manages multi-source XMLTV ingestion using a Channel-based producer-consumer architecture. Downloads run concurrently (Semaphore-gated: 3 on mobile, 2 on TV), and ingestion into the DB is parallelized (2 workers) via an `UNLIMITED` Channel queue. User-initiated refreshes and the on-connect `refreshOutdatedSources` are submitted through `RefreshQueue`; `EpgSyncWorker` (the periodic auto-refresh) calls `processAllSources` → `processAllSourcesInternal` directly so the work stays under the worker's wake lock on Shield/Doze.
- **Stale Threshold:** per guide source, its full `epg_source.refresh_interval_hours`, 24 h when off (`EpgRefreshSchedule.staleAfterMs`; null = not set uses the retired device-wide interval); an automatic run takes a source up to an hour before that (`isDue`, WorkManager jitter). `EpgSyncWorker` runs at the shortest interval among enabled sources and refreshes the due guide sources of every source Search the guide reads (`GuideScope`: the profile's sources with channels — Xtream, M3U), in one inline run that has each guide source one time; an off source (-1) only while never ingested, and counts as stale after 24h for Refresh stale. See `docs/epg_guide.md` → Refresh scheduling.
- **Indexing:** `EpgIndexer` parses XMLTV into `epg_index.db` (Room, version 18) using FTS4. The `ingest_method` column tracks how each source was ingested.
- **Search:** Two-tier strategy, both via SQLite **FTS4 MATCH** in `XmltvSearchService`: a raw query preserving FTS operators (OR/NEAR/NOT, prefix wildcard), then a sanitized "safe" AND-style retry if the raw query returns nothing. If the index isn't built yet (`EpgIndexState.NotIndexed`), search returns null. If the FTS index is stale (`isFtsStale()` — a low-storage direct-path refresh, or an interrupted rebuild), search falls back to a title-only `LIKE` scan of `epg_programme.title_lowercase` (`EpgSearchPath.LIKE_FALLBACK`, same window/500 cap/10 s timeout; the screens note results may be incomplete); only if that times out or fails does it throw `EpgIndexBusyException`. `EpgBrowserViewModel` shows `UiState.IndexBusy` (why, not "no results") and reruns a busy or `LIKE_FALLBACK` query when `EpgIndexer.state` reaches `Indexed` — so `rebuildFtsAndUpdateState()` clears the stale flag *before* publishing `Indexed`. The staging path never goes stale: `EpgIndexer.swapAndRebuildFts()` does the staging→primary swap and the FTS `'rebuild'` in one transaction, so WAL readers never see new rows with the old FTS — keep them together. No XML-scan fallback exists.
- **Timezone:** Per-source `timezoneOffsetHours` override applied at parse time.
- **State Machine:** `MultiSourceState` sealed interface: `Idle` -> `Processing` -> `Completed`/`Error`, plus `Clearing` state. Per-source progress tracked via `ActiveSourceProgress(label, phase, channels, programmes)`.
- **Change Detection:** `downloadSource` sends `If-None-Match`/`If-Modified-Since` from the source's stored `etag`/`last_modified_header`; a `304` short-circuits with no body read. Otherwise a SHA-256 of the payload is compared to `last_content_sha256` (computed during the download pass for plain sources, after decompression for `.gz` — gzip's mtime header taints the raw bytes). A confirmed-unchanged source skips `ingestFromStream` entirely, is excluded from `swapAndRebuildFts`'s id list (its staging table was never populated), and carries its previous counts forward via `EpgSourceDao.markUnchanged`. A hash match only skips within 24h of the last real ingest. Ingest has no date filter: every programme the source provides, past or future, is kept.
- **Download Integrity:** `read()` returning -1 alone can't distinguish a clean EOF from a cut connection. `totalRead` is checked against `Content-Length` when the server sends one; a mismatch is a download error and takes the normal retry path.
- **Persistent Stats:** Pipeline completion triggers an update to `EpgPipelineStatsEntity` in `providers.db` (`SettingsDatabase`, version 21).
- **Clear All Data:** Uses DB `destroy()` + `getInstance()` (recreate) instead of `DELETE FROM` — critical for performance on large databases (4M+ rows). Cancel in-flight work via `RefreshQueue.cancelAll()`.
- **ViewModel Resilience:** `EpgManagementViewModel` uses a `db()` function (always calls `EpgIndexDatabase.getInstance()`) and `_dbGeneration` StateFlow counter. After DB destroy/recreate, bumping the generation causes `flatMapLatest` to re-subscribe all Room Flows to the new DB instance.
- **Management:** Multi-source EPG management in `Screen.EpgManagement`.
- **Guide source links:** a guide source serves its sources through `epg_source_provider`, and its channels are matched for each linked source. Never merge a source's own Xtream guide (`<host> (Bulk)`) with another guide source: two logins on one server have the same stored URL but different channels.

Settings is Your Profile, the five Admin sections (Profiles, Parental Controls, This Device, Sources & Guide, Sync & Backup) under an Admin heading, and About (About Fijerena, Device Info, Logs) (the admin settings plan and the Admin sections plan). Without Admin, Settings is Your Profile and About. The rule: a setting of the whole household or the whole device goes in Admin; a setting of one profile goes on the profile's page, and Your Profile shows only its personal rows (a profile's Admin rows show only in the Profiles section: `adminRows` on TV, `Screen.ProfileEdit.admin` on the phone). It is "Admin" in the UI text and "admin" in the code (`AppSettings.isAdmin`, `ProfileActor.isAdmin`, `isAdminOnly`, `AdminGroup`): never "Expert" or "developer mode". A profile's optional PIN (`ProfilePins`, `PinSession`) is asked only before what changes shared setup or another profile — in Settings, once for each session, when the first Admin section opens (`SettingsGroup.adminOnly` on TV, `AdminGroup` on the phone; a new row in a section is guarded without a line of its own), and the screens they open (`isPinGuarded`) — never on opening Settings, Your Profile, picking a profile or at launch, except the child lock (off in code, `SwitchLock.ON`): when on, leaving a child profile asks an admin's PIN while one has a PIN (`ProfilesViewModel.switchTo`, `SwitchLock`). On TV, Settings is a rail (Your Profile, the five Admin sections under an "Admin" heading, About) beside the focused entry's rows; on the phone, the Admin sections are rows under an Admin header, each opening its own page.
- **Profile roles (Child, Admin, Nerd):** each is a per-profile synced flag (`child_profile`, `admin`, `nerd_mode`). `ProfileRules` (core/ui) decides who changes what, below the screens; the editors only hide what is not allowed. Nerd (`AppSettings.nerdMode`, `LocalNerd` in composables) shows the stats and extra information and gives no right to manage: never gate a management action on it. A kid is never a Nerd: `nerdMode` reads false for a child, and every path that makes a profile a child clears the stored flag (`ProfileRepository.setChildProfile`, `clearChildAdmins` after a sync, the settings import). Only an admin adds a Nerd or changes another grown-up's Nerd; a grown-up changes its own Nerd with no PIN. No "last Nerd" guard, and no copy from Admin.
- **TMDB is opt-in:** no release build carries a key (D4, the public release plan; a debug build seeds one from `TMDB_API_KEY` in `local.properties`, `BuildConfig.DEBUG_TMDB_API_KEY`); the user enters theirs in Settings (`TmdbKeyStore`, encrypted, synced as `tmdb_api_key`). Every TMDB call goes through `TmdbApiService`, which reads the key per call and throws before any request when there is none; a 401 marks the key rejected, which then reads as no key. Check `hasApiKey()` before spending TMDB work, and keep every TMDB-only section (logo, related rows, age rating) absent rather than empty when it returns nothing.
- **Sports sources are gated and followed-only:** every call to a sports service (ESPN, NHL, MLB) goes through `SportsData` and its `SportsApi` (`core:network/sports`), never a client of its own. Admin's **Sports** switch (`AppSettings.showSports`) gates all of it: off, no sports API is called and every sports screen, rail item, tab, Home row and bell is absent. Never call a sports API for a child profile, and show no sports UI there. Read only what the profile follows (`FollowedSports`): the Sports section, Home's Upcoming Games, reminders and the cache refresh read the followed teams' schedules and the followed leagues' games, nothing else; a page opened from search reads its own games once. The live channels a game is matched to come from one loader (`ReminderChannelFinder.liveChannels`). A game shows only the profile's channels, guide programmes and PPV or event channels that carry it (`GameChannelMatcher`); a network's name (ESPN's, the NHL's, MLB's) is used only to find channels with that name, never shown as a list of where the game is on. No TV-rights table or per-country broadcaster source.
- **Database Maintenance & Compaction:** When providers are deleted, `ProviderRepository.deleteProvider` cascades through all catalog tables in `xtream_v2.db` (`xtream_streams`, `xtream_series`, `xtream_episodes`, `xtream_categories`, `favorite_state`, `xtream_epg_cache`), clears orphaned SharedPreferences (`provider_creds_*`, `media_cache_*`, `xtream_cache_*`), deleting catalogue rows 1,000 per commit; no automatic `VACUUM` (`auto_vacuum = FULL` already returns space, and a WAL-mode `VACUUM` needs room for the whole database — see `docs/DATABASE_SCHEMA.md` §3). A background sweep (`sweepOrphanedCatalogData`) runs during `EpgSyncWorker`, and at app start only after an interrupted deletion (`orphan_sweep_pending`); it removes downloaded catalogue only, never favourites or watch history, and never throws. The "Shrink Database" button in Settings is the only place a `VACUUM` runs, and the only path that removes orphaned credential files and EPG sources. A circuit breaker prevents deletions if the valid provider list is empty.

Compose UI tests are Robolectric unit tests (`src/test`), never `androidTest`: they run in CI and touch no device. Build, deploy and debugging details are in `docs/RUN_GUIDE.md`.

### Deployment Rules

- **Use the deploy scripts**, never hand-run `gradlew` + `adb install`. They build incrementally and install with `install -r`. `deploy-tv-emulator.sh` and `deploy-tv-ip.sh` check `dumpsys media_session` for active playback (`state=PlaybackState {state=3}`) and ask before interrupting it; `deploy-tv-ip.sh` skips a device that doesn't report `tv` in `ro.build.characteristics`. The TV app is `org.njarasoa.fijerena` and the phone app `org.njarasoa.fijerena.mobile`; `scripts/app-package.sh <serial>` prints a device's, and the backup, restore and uninstall scripts use it.
- **NEVER install to real hardware without backing up app data first.** `adb install -r` is *not* guaranteed to preserve app data — a signing-key mismatch (or other cause) can make it install fresh with no warning. On 2026-09-08 a deploy to three real TVs reported "Success" on every device and had wiped every one (`firstInstallTime == lastUpdateTime`); no backup existed. `deploy-tv-ip.sh` and `deploy-mobile-usb.sh` back up each device with `scripts/backup-app-data.sh` (user data only: `shared_prefs`, `providers.db*`, and the `watch_state`, `favorite_state`, `wanted_title`, `followed_sport`, `game_reminder` and `sync_*` tables of `xtream_v2.db`) into `backups/`, deleting backups older than 7 days, and don't install on a device whose backup failed; `scripts/restore-app-data.sh` puts one back. Any other install to a real device runs `scripts/backup-app-data.sh <serial> <out.tar.gz>` first. One exception (maintainer decision, 2026-10-21): USB phones get the non-debuggable `localRelease` build by default, which run-as cannot back up; `deploy-mobile-usb.sh` warns and installs, and the shared debug signing key keeps the data. Permission to deploy is not permission to skip this.
- **Never uninstall or clear app data** (`adb uninstall`, `pm clear`) to fix a deploy. On emulators, installing over the existing app (the deploy scripts, `install -r`) is fine. `scripts/uninstall-app.sh` is the only sanctioned uninstall and asks for confirmation. `./gradlew connectedAndroidTest` uninstalls the app on every connected device: run it on one emulator only (`ANDROID_SERIAL`).
- **Incremental deploys:** the deploy scripts don't run `clean`. A `NoClassDefFoundError` after changes across modules (`core:*` consumed by `:tv`/`:mobile`) is a stale DEX shard: `./gradlew clean`, then deploy again.
- **Finding devices:** network TV IPs drift (DHCP, `192.168.1.0/24`). Run `adb mdns services` first; fall back to `arp -a | grep 192.168.1.` only if it finds nothing. Identify a device by `getprop ro.build.characteristics` (`tv` vs `default`/`nosdcard`) or `product:`/`model:` in `adb devices -l`, never by IP or port — emulator serials follow launch order.

### Schema Changes

**Every Room migration updates `docs/DATABASE_SCHEMA.md` in the same commit.** Not as a follow-up. That doc is the only prose description of the schema, so a migration that lands without it leaves the file stating a version number the code no longer uses - which is exactly how it drifted before (`providers.db` documented as v8 when it was v10, `xtream_v2.db` as v14 when it was v15).

A migration means any of: a new `MIGRATION_n_n+1`, a version bump, a new entity, a new column, a new index. For each, update:

- the database's `**Version:**` line;
- the parenthetical migration history in that section's intro ("v15 added `watch_state`…"), appending the new entry;
- a full table section for a new table - every column with type and description, the primary key, and each index;
- any new SharedPreferences key the migration introduces, especially one-time backfill/purge flags (`watch_state_migrated_v1`, `favorites_migrated_v1`), in the scalar-keys table of §4;
- when a migration replaces a SharedPreferences blob: remove that key from the §4 table and add a **Retired:** note naming the table that now owns it and the backfill hook that copies it.

**Commit the generated Room schema too.** `xtream_v2.db` and `providers.db` export their schema (`exportSchema = true`, KSP `room.schemaLocation`) to `core/network/schemas/<database class>/<version>.json`. The build writes the new version's file; commit it with the migration. CI fails if a build leaves an uncommitted change there (an entity changed without a version bump) or finds a blanket `fallbackToDestructiveMigration(` in either database. History starts at `xtream_v2.db` v24 / `providers.db` v15 — older versions have no JSON.

## Performance & Bug Journal

Hard-won lessons from production debugging. Read these before making changes in related areas.

### SharedPreferences JSON deserialization was the #1 hotspot
**Context:** The favourites getters deserialized JSON from SharedPreferences on every call with no in-memory cache, and were called per-chip inside `LazyRow items {}` — 500+ deserializations per recompose for large providers.
**Fix:** In-memory cache + dirty-flag + debounced write (the pattern `cachedWatchHistory` uses). Since 2026-08-28 favourites and watch state live in Room (`favorite_state`, `watch_state`), read through `MediaRepository`'s in-memory snapshots, so those blobs are gone; the rule still applies to any SharedPreferences JSON read in a hot path.

### Watch history lookups were O(n*m) in refreshPerItemData
**Context:** `MediaRepository.getPlaybackPosition()` did a linear scan of the watch-history blob per call, and `refreshPerItemData()` called it in a loop over every stream.
**Fix (landed):** `getPlaybackPositions(contentType)` now issues one indexed `watch_state` query and returns a Map for O(1) lookups. The lesson stands: always check for linear scans inside loops when profiling data layers.

### contentHash self-referential hash bug in XtreamContentManager
**Context:** `hashCode()` on a data class that includes the `contentHash` field (defaulting to 0). The stored entity has a non-zero `contentHash`, so `hashCode()` never matches — causing spurious DB re-inserts on every sync.
**Fix:** Exclude the hash field itself from `hashCode()` computation.

### Every catalog sync rewrote most rows and wiped their detail cache
**Context:** Xtream's `num` is a position in the provider's list; it shifts for tens of thousands of rows whenever the provider adds one (38,888 of 47,513 series between two panel-a syncs 3h apart). It was in `contentHash`, and a changed row is rewritten with `@Insert(REPLACE)` from a fresh entity, which reset `episodesFetchedAt`, `detailFetchedAt`, `contentRating`, `posterPath` and `containerExtension`.
**Fix:** `computeHash` leaves `num` out; a stream whose position alone moved gets `updateNums` (lists are ordered by `num`); changed rows go through `insertKeepingDetailCache`, which carries the detail columns over (a changed series still clears `episodesFetchedAt`, the "fetch its episodes again" trigger). **Rule:** a catalog hash covers content only, never list position; never write a catalog row with a bare `insertAll` from sync code. See the catalog sync cache churn plan.

### Clear All EPG Data takes 10+ minutes with DELETE FROM
**Context:** 4M+ rows on NVIDIA Shield with low-IOPS flash storage.
**Fix:** Replace row-level deletion with DB `destroy()` + `getInstance()` (recreate). Use `db()` function + `_dbGeneration` counter to re-subscribe Room Flows after recreation.

### EPG pipeline lacked feedback between download and ingestion
**Context:** Channel-based producer-consumer pipeline decouples downloads from ingestion. Large source finishes downloading but sits silently queued.
**Fix:** `EpgFileManager` emits an explicit `"Awaiting Ingestion"` phase (`ActiveSourceProgress.phase`) once a source is sent to the ingestion channel.

### Compose recomposition hotspots from un-hoisted allocations
**Patterns to avoid:**
1. `collectAsState()` instead of `collectAsStateWithLifecycle()` — keeps flows active when backgrounded.
2. `Color.copy()` called inside composables — allocates every frame.
3. `System.currentTimeMillis()` / `Date()` inside composable bodies without `remember {}`.
4. `Brush.verticalGradient()`, `ButtonDefaults.colors()`, `FilterChipDefaults.filterChipColors()` allocated inside composables instead of hoisted.
5. `AppSettings` deserialized inside tight loops (e.g., `while(true)` in `EpgFileManager`).

**Rule:** Hoist allocations that don't depend on recomposition state to `remember {}` or outer scope. Prefer `collectAsStateWithLifecycle()`. Treat SharedPreferences deserialization as expensive.

### Category references treated as streams on long-press
**Context:** Virtual categories render entries as `MediaItem` with `providerData["isCategoryRef"] = "true"`. Long-press handlers were creating `Stream` favorite targets for ALL items.
**Fix:** Always check `providerData["isCategoryRef"]` before deciding the favorite target type.

### FTS count crossed with an indexed IN-list took seconds per query
**Context:** Search showed "Loading categories…" (the default `UiState.Loading()` label) for ~45 s for "the" on a 250k-row Xtream provider. Not the category load and not the search: `countExcludedByFts` (`s.rowid IN (fts MATCH) AND s.categoryId IN (excluded categories)`) let SQLite pick the `(providerId, type, categoryId)` index and probe every excluded category × every FTS docid. Host test DB: 4.95 s (VOD) + 5.6 s (Live) for "the*" vs ~20 ms for the LIMIT 200 search itself.
**Fix:** `+s.categoryId` (unary plus disables that index) so the FTS docids drive the lookup: 0.05 s / 0.02 s, same counts. **Rule:** when a query combines an FTS `rowid IN (… MATCH …)` with another `IN` list on an indexed column, run `EXPLAIN QUERY PLAN` on a full-size catalogue with a short common prefix before shipping.
